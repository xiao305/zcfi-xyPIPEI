# zcfi-xyPIPEI 商品管理与智能扫码

> 一个**不需要服务器**的轻量商品管理工具：页面托管在 GitHub Pages，数据只保存在你自己的 **GitHub Gist**。
> 没有数据库、没有后端、没有账号体系；打开网页，用自己的 GitHub Token 连接自己的 Gist 即可使用。

- 站点入口：`https://xypipei.zcfi.cn/`（导航页，选择下面两个入口）
- 管理后台：`https://xypipei.zcfi.cn/admin`（商品树、库存、回收站、数据工具、标签打印）
- 智能扫码：`https://xypipei.zcfi.cn/scan`（手机端连续扫码、关联快递/订单/链接、标记售出）
- 当前版本：**v2.3.7**（核心 `js/core.js` v2.3.0 / 管理后台 **R5** / 扫码端 **R3**），文档更新日期 **2026-11-14**；v2.3.7 完成管理后台界面降噪与渐进式披露重构（去除重复标签、操作按钮收纳进 ⋮ 菜单、状态标签轻量化、汇总改紧凑文本、勾选后才显示跨节点批量操作）；v2.3.6 修复长编码条码错位。

> ## ⚠️ 使用前必读：Secret Gist 不是私有仓库
>
> GitHub 的 **Secret Gist 只是「不公开列出」，并不等于私有**：拿到链接的人**无需登录**就能查看/下载内容（公开 Gist 甚至可能被搜索到）。也就是说——**链接即权限**。
>
> - **不要把成本价、订单号、快递单号、客户信息等敏感数据**放到地址可能被猜到/传播的 Gist 里；
> - 需要更稳妥时：使用**专用 GitHub 账号**只放这套数据、定期**轮换 Token**、Gist 地址只给可信的人；
> - 本系统没有服务端鉴权，Gist 的可见性就是唯一防线。数据安全的第一责任人是 Gist 的所有者。

> 详细上手步骤见 [用户手册](docs/USER-GUIDE.md)，备份/恢复见 [备份与恢复](docs/BACKUP-AND-RECOVERY.md)，常见问题见 [FAQ](docs/FAQ.md)，技术结构见 [架构说明](docs/ARCHITECTURE.md)，发布流程见 [发布检查清单](docs/RELEASE-CHECKLIST.md)。

## 一分钟了解

| 页面 | 用途 | 适合设备 |
| --- | --- | --- |
| `/` | 站点导航页：两个入口 + 安全提示（纯静态、无脚本、无 CDN） | 全部 |
| `/admin` | 建商品树、维护库存、搜索排序汇总、批量/复制、回收站、导入导出、历史版本恢复、打印标签（7 套模板：公共/入库/出库） | 电脑（Chrome/Edge），也兼容平板/390px 手机宽 |
| `/scan` | 扫内部编码/订单号/快递单号/链接，查商品、关联快递、标记售出、连续扫码、图片识别 | 手机（Safari/Chrome） |

数据流向：

```
手机 / 电脑浏览器（/admin、/scan）
        │  读取 / 保存（HTTPS，GitHub Token 只在 Authorization 头）
        ▼
GitHub Gist 的 data.json（你自己的 Gist —— Secret 也只是「不公开列出」，不是私有）
```

- **没有服务器**：所有页面是静态 HTML，浏览器直接调用 GitHub API。
- **数据只存 Gist**：除了 GitHub，页面不向任何其它服务器上传商品数据。
- **图片识别在本机完成**：相册图片不会上传。
- **扫码库已本地化**：`js/vendor/html5-qrcode.min.js`（自托管，锁 2.3.8），不再依赖任何 CDN。

## 适用场景

- 自己或小团队管理二手/库存商品：一个商品有多个子类、多个库存件，需要内部编码。
- 需要给商品/库存打印内部编码标签（二维码/条形码）。
- 手机扫一下编码或快递单号，就能看到商品详情，并把快递单号、订单号、购买链接关联到对应商品。
- 发件/出货时顺手把商品标记为「售出」，回电脑端继续对账。
- 不想租服务器、不想维护数据库，数据放自己的 GitHub Gist 最省心。

> **不适合**：存放高敏感经营数据（成本、客户信息、订单明细）。Gist 没有真正的访问控制，**Secret Gist 不是私有**，拿到链接即可读取。确需使用请自行评估风险，或改用带鉴权的存储。

## 首次使用（5 步）

### 第 1 步：创建一个 Gist（数据文件）

1. 打开 <https://gist.github.com>（GitHub 账号）。
2. 文件名填 **`data.json`**。
3. 内容先填：

   ```json
   {"schemaVersion":1,"products":{}}
   ```

   （`schemaVersion` 是数据结构版本，当前为 `1`；旧数据没有该字段也能正常读取，保存时会补写。）

4. 创建后，地址栏最后一段就是 **Gist ID**（一长串十六进制字符），复制保存。
5. Gist 可见性建议选 **Secret**（至少不会被公开列出）。但必须清楚：**Secret Gist 不是私有仓库**，任何拿到链接的人都能读取内容；**不要把敏感数据放进去**。

> 登录页的 **Gist ID 默认是空**的——**必须填写你自己的 Gist ID**，不存在可直接使用的示例值。

### 第 2 步：创建 GitHub Token

推荐 **Fine-grained personal access token**（细粒度 Token）：

1. 打开 GitHub → 右上角头像 → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**。
2. 只需要勾选 **Gists: Read and write**（读取和写入 Gist）。其它权限一律不给。
3. 有效期按需选择（例如 90 天），到期前记得换新 Token。
4. 生成后**只显示一次**，立即复制保存。

如果已熟悉 Classic Token，也可以用 Classic Token 并**只勾选 `gist` 权限**。

> - Token 只需 **`gist` 权限**（Classic）或 **Gist 读写**（Fine-grained），不要给仓库/组织等其它权限。
> - Token **只保存在本机浏览器**，但会**随每次请求通过 `Authorization` 头发送给 `api.github.com`**（这是 GitHub API 的必需方式）。它不会进 URL、不会写进 Gist、不会发给其它域名。
> - Token 相当于你的 GitHub 密码的一部分：**不要发给别人、不要贴到聊天/截图/代码仓库里**。如果怀疑泄露，立即到 GitHub 撤销并重新生成。
> - `gists` 权限是**账号级**的：Token 泄露 = 该账号下**所有** Gist 可被读写。建议专用账号 + 定期轮换。

### 第 3 步：登录页面

打开 `/admin` 或 `/scan`，填写：

| 字段 | 填什么 |
| --- | --- |
| GitHub Token | 第 2 步生成的 Token（`ghp_...` 或 `github_pat_...`） |
| Gist ID | 第 1 步复制的 Gist ID（**登录页默认为空，必须填写自己的**） |
| 文件名 | `data.json`（必须与 Gist 中的文件名一致） |

点击「登录」。

> 登录框的 Gist ID 没有任何默认/示例值（v2.2.0 起已移除硬编码默认值），留空无法登录。

### 第 4 步：先在后台建商品

登录 `/admin`：

1. 点「＋ 添加大类」→ 填名称（编码自动生成）。
2. 在分类下点「添加子类」或「添加库存」（取决于「类目条码」设置（是=加子类，否=加库存））。
3. 按需填写成本、快递单号、订单号、备注、链接、状态。

完成后刷新 `/scan` 即可扫码。

### 第 5 步：手机扫码

打开 `/scan` → 点「开始扫码」→ 允许摄像头 → 对准内部编码/二维码/条形码。

- 首次打开摄像头需要 HTTPS（GitHub Pages 默认是 HTTPS）。
- 如果扫码不成功，可以用「图片识别」从相册选一张二维码截图，或用手动输入框输入编码。

### 关于「记住登录」

- `/admin` 与 `/scan` 都有「记住登录（本机）」勾选项，**默认不勾选**：
  - **勾选**：凭据存到 `localStorage`，关闭浏览器后再打开仍自动登录。
  - **不勾选（默认）**：凭据只存到 `sessionStorage`，关闭标签页/浏览器后失效。
  - 读取时 `sessionStorage` 优先于 `localStorage`（两页一致）。
  - 退出登录会同时清理两处凭据；切换勾选状态时会清理另一种存储，避免残留旧 Token。
- **共用设备风险**：勾选「记住登录」等于把 Token 留在本机浏览器里，任何能使用这台电脑/浏览器的人都可能读到并操作用你的 GitHub 账号下的 Gist。公共/共用设备请**保持默认不勾选**，用完点「退出登录」。
- 退出登录会清理凭据；扫码端还可选择**同时清理本机扫码历史**（历史含快递单号等，共用设备建议一并清理）。
- Token 始终**只在本机浏览器**，页面上传的只有对 GitHub API 的请求。
- 如果两页使用同一浏览器，登录状态可以互通；遇到自动登录成旧账号/旧 Gist，先在两个页面都「退出」，必要时清理浏览器站点数据再登录。

## 数据模型与编码规则

一个 Gist 文件 `data.json` 保存整棵树：

```json
{
  "schemaVersion": 1,
  "products": {
    "A001": {
      "name": "相机套机",
      "unified": true,
      "cost": 1200,
      "trackingNumber": "JT0001234567890",
      "orderNumber": "ORD20261001001",
      "remark": "测试大类",
      "qrLinks": ["https://example.com/p1"],
      "status": "在售",
      "deletedAt": null,
      "children": {
        "A001/B001": {
          "name": "相机-黑色",
          "unified": false,
          "items": [
            {
              "code": "A001/B001/001",
              "name": "黑色库存1",
              "cost": 800,
              "status": "在售",
              "trackingNumber": "SF1234567890123",
              "orderNumber": "ORD20261001002"
            }
          ]
        }
      }
    }
  }
}
```

### 字段说明

| 字段 | 含义 | 谁维护 |
| --- | --- | --- |
| `schemaVersion` | 根级数据结构版本，当前 = `1`；缺失视为旧版，保存时补写 | 系统 |
| `name` | 商品/分类/库存名称 | 后台 |
| `unified` | **类目条码**（原“统一条码”）：是=整个类目共用一个编码、不记成本/快递/订单，状态由类目下商品自动汇总；否=单件条码，每个库存单独编码并可记成本/单号 | 后台 |
| `cost` | 成本（数字，可留空） | 后台 |
| `trackingNumber` | 快递单号 | 后台 / 扫码关联 |
| `orderNumber` | 订单号 | 后台 / 扫码关联 |
| `qrLinks` | 关联链接数组（例如购买链接、核销链接） | 后台 / 扫码关联 |
| `remark` | 备注 | 后台 / 扫码备注 |
| `status` | `待售` / `在售` / `售出`；旧数据里的「已售」会自动显示为「售出」 | 后台 / 扫码标记售出 |
| `deletedAt` | 软删除标记。有值=在回收站；普通页面和扫码都不再显示 | 后台回收站 |
| `children` | 子类（key 为子类编码） | 后台自动 |
| `items` | 库存项数组（每个库存是独立一件商品） | 后台自动 |

> 根级的**未知字段会被保留**：保存/恢复时只替换 `products`（以及 `schemaVersion`），不会清掉远端根对象上其它字段。

### 类目条码（`unified: true`，原“统一条码”）

- **含义**：类目条码代表“整个类目”，不是单件商品；扫这个码得到的是类目，而不是某一件库存。
- 开启类目条码后：**不记录成本 / 快递单号 / 订单号**（保存时自动清除），节点状态改为**由类目下商品自动汇总**：`全部在售` / `部分在售` / `全部售出` / `部分售出` / `全部待售` / `部分待售` / `无库存`。
- 关闭（`unified: false`，单件条码）：每个库存单独编码，可记录成本/快递/订单，并手动维护状态。
- 后续会支持“部分出库”等更细的类目状态（属于后续大版本）。

### 内部编码规则

| 层级 | 格式 | 示例 |
| --- | --- | --- |
| 大类 | 默认 `A` + 三位数字；可自定义 | `A001`、`NN` |
| 子类 | 父编码 + `/` + 本级段（默认 `B` + 三位数字；可自定义本级段） | `A001/B001`、`NN/YO1` |
| 库存 | 父编码 + `/` + 本级段（默认三位数字；可自定义本级段） | `A001/B001/001`、`NN/YO1/002` |

- **自定义编码规则（v2.3.0）**：本级段只允许**英文字母 + 数字（可混搭）**，如 `AB12`、`YO3`、`X1`；**不允许中文**、空格与特殊符号。
- **子类/库存只能改本级段**：父编码前缀由系统固定展示、不可修改；例如父 `NN` 下自定义子类只填 `YO3`，完整编码为 `NN/YO3`。
- **自动生成会跟随同级格式（v2.3.0）**：同级已有 `NN/YO1`、`NN/YO2` 时，新建子类默认给出 `NN/YO3`（字母前缀 + 递增数字，位数沿用）；已有 `A001`、`A002` 则给 `A003`；没有同级时回退旧默认（`A001` / `B001` / `001`）。
- 高级用户可勾选「自定义编码」手填；**节点编码与库存编码全局唯一**（比较时忽略大小写）。
- 后台改名会级联更新子类和库存编码；**改名后旧标签/旧二维码可能扫不到**，需要重新打印。
- 扫码端匹配时会统一编码：`normalizeCode` 会**去除零宽字符与所有空白（含全角空格）**，再忽略字母大小写比较；后台编辑时请保持格式规范。

## 日常使用：扫码端 `/scan`

### 扫码查商品

1. 登录后点「开始扫码」，允许摄像头。
2. 对准二维码/条形码/PDF417；识别成功会震动/提示音（可在「更多 → 设置」关闭）。
3. 命中的商品会用**底部抽屉**展示：名称、编码、状态、成本（默认隐藏，可点显示）、快递、订单、备注。
4. **连续模式**（默认开启）：关闭抽屉后摄像头不会重启，可直接扫下一件。
5. 顶部「连续模式」开关可关闭；关闭后每次扫码会停止摄像头，需要手动再点「开始扫码」。

### 未找到 / 多个匹配

- 没找到：弹出提示，点「继续扫描」直接回到扫码；也可查看历史。
- 同一订单号/快递号命中多个商品：弹出候选列表，顶部黄条提示「该单号命中 N 个商品，请确认」，点选正确的那个再进详情。
- 命中回收站中的商品：提示「该商品已删除，请到后台回收站恢复」，不会进入详情。

### 关联快递单号 / 订单号 / 链接

1. 在商品抽屉里点「扫描关联信息」。
2. 扫描（或手动输入）要关联的内容：
   - `https://...` → 识别为链接
   - 常见快递单号格式 → 识别为快递单号
   - 其它 10 位以上纯数字 → 识别为订单号
   - 识别不准时，可在弹窗下拉框里手动改类型。
3. 若该商品已有同类型值，会提示「替换」或「已绑定相同」。
4. 勾选「关联后标记为售出」可同时改状态；点「确认关联」保存。
5. 成功后可点「继续扫下一件」回到扫码。

> 扫码端只写 `trackingNumber` / `orderNumber` / `qrLinks` / `remark` / `status` 这些字段；名称、成本、编码、统一条码请在后台改。

### 冲突处理（逐字段）

如果后台/另一台设备同时改了同一字段，扫码端会弹出**逐字段冲突对话框**，列出「基准值 / 远端值 / 我的值」，可逐项选择「用我的」或「用远端」，不再是简单的一句“确定覆盖”。

### 图片识别

- 点「图片识别」→ 从相册/文件选择二维码或条形码截图 → 自动识别并走同一套查询流程。
- 图片只在本机浏览器中解码，不会上传。
- 识别失败时换一张更清晰、二维码占比更大的图片。

### 手电筒 / 提示音 / 震动

- 手电筒按钮只在设备/浏览器支持时显示；不支持时自动隐藏。
- 「更多 → 设置」里可关闭扫码震动、提示音；设置保存在本机。
- 手机默认静音时提示音可能听不到，可依赖震动。

### 历史记录

- 扫码端历史只保存在**本机浏览器**（不写 Gist），按日期分组，点击可回看商品。
- 历史按 **Gist ID 隔离**：换账号/换 Gist 不会看到上一次的数据；退出登录时可选择一并清除本机历史。
- 如果历史对应的商品已被删除（或已不存在），该条会置灰并显示灰色「已删除」徽章；点击仍提示「该商品已删除，请到后台回收站恢复」，不会打开详情。
- 「更多 → 清空历史」会二次确认；清空后 12 秒内可点底部「撤销」（保留最近 20 条备份），撤销窗口结束后备份会被删除。
- 历史不是库存数据，清空它不会影响 Gist。

### 多标签页

- 多个标签页同时打开时，登录/退出/历史会通过 `storage` 事件同步；退出会在各标签页生效。
- 两端同时扫码时历史按记录合并，而不是整键覆盖。

### 数据新鲜度 / 离线（错误分类）

- 页面顶部显示「数据更新于 HH:mm」，点右侧 ⟳ 可手动刷新；下拉刷新/重新打开页面也会重新拉取。
- 扫码命中先用本地缓存立即匹配；后台每 30 秒自动刷新一次，页面重新可见时也会刷新。
- **只有网络问题才进入离线模式**（`NETWORK` / `RATE_LIMIT` / `SERVER`）：此时显示离线提示，仍可用缓存匹配。
- `AUTH`（401）会要求重新登录；`PARSE` / `SCHEMA` / `TRUNCATED` 等数据损坏类会明确报错并**禁止写入**，避免用残缺数据覆盖远端。
- 保存关联/备注时会重新联网校验，失败会提示并可重试。

## 日常使用：管理后台 `/admin`

### 商品树 / 搜索 / 排序 / 汇总（R2b 起，R4 修复）

- 顶部汇总条：节点数、库存数、在售/售出/待售数量；每个节点行也有子类/库存/状态汇总。
- 汇总**不会统计回收站子树**：软删除的父节点及其下未删除的子项都不计入（R4 修复）。
- 搜索框：**200ms 防抖自动搜索**，支持编码、名称、订单号、快递单号、备注、状态、链接，命中文字高亮；**中文输入法组合期间不触发重渲染**（R4 修复）。
- 筛选：按大类筛选时会**显示该大类下的子类与全部库存**（R4 修复）；节点排序（编码/名称/更新时间升降序）；库存表头可点击按编码/名称/成本/快递/订单/状态排序。
- 视图记忆：搜索词、筛选、排序、展开状态保存在本机（`zcfi_admin_view_v1`），刷新后恢复。
- 快捷键：`Ctrl/Cmd + F` 聚焦搜索；`Ctrl/Cmd + S` 保存当前编辑弹窗；`Enter` 在弹窗内保存；`Esc` 关闭当前弹窗/菜单。
- 响应式：窄屏（约 390px）自动换行/全屏弹窗/44px 触控目标；宽表格可横向滚动。
- 节点行显示：名称、编码、状态、紧凑汇总（如 `子类:1 库存:3（在售2, 待售1）`）；库存表显示：编码、名称、成本、快递单号、订单号、状态、备注摘要、链接数。
- **v2.3.7 界面降噪**：去掉「类目/单件」徽章、📋 订单号徽章与「无库存」标签；状态标签统一为浅底小标签；节点/库存行只保留「编辑」「打印标签」两个核心操作，其余（添加、复制、打印全部库存、复制编码、删除）收进行尾 **⋮ 菜单**；顶部「跨节点批量改状态/批量打印」只在勾选了任意库存后平滑出现。

### 编辑 / 复制 / 批量新增 / 跨节点批量

- 编辑节点/库存：名称、编码（高级自定义）、类目条码、状态、成本、快递单号、订单号、链接（多个用逗号或换行分隔）、备注。
- 行尾 **⋮ 菜单**里的「复制」：复制字段生成副本（节点名加「（副本）」），编码自动生成；嵌套节点会复制到**正确的父节点**下。
- 行尾 **⋮ 菜单**里的「复制编码」：一键复制到剪贴板。
- 「添加库存」可填数量（1–100）：一次保存批量生成 `…/001`、`…/002`… 连续编码的 N 件库存。
- 库存行勾选后可「批量打印」「批量修改状态」；勾选「全选当前筛选结果」后，顶部才会平滑显示并启用**跨节点**批量改状态/批量打印（未勾选时默认隐藏）。
- 保存时只提交实际改动的字段；如果其它设备/扫码端同时改了同一字段，会弹出冲突对话框，逐项选择「用我的」或「用远端」。
- 新建编码使用 `createOnly` 语义：两端并发新建同码时不会静默覆盖，会提示刷新。

### 回收站（软删除）

- 「删除」默认只是**移入回收站**（数据仍在 Gist 中，设置 `deletedAt`）。
- 回收站中的商品不会出现在树、搜索、打印、扫码端；恢复后重新可见。
- 回收站可「恢复」或「彻底删除」（永久移除，不可恢复）。
- 删除父节点会隐藏整棵子树；恢复子节点前必须先恢复父节点（祖先守卫已修复，会正确判断上级编码）。
- 彻底删除后，对应编码才会从「全局唯一」占用中释放，可重新使用。

| 功能 | 说明 |

### 本地快照与恢复

- 快照按 **Gist ID 分桶**保存，列表会显示归属；切换 Gist / 退出登录后不会看到（或恢复）其他账号的快照。
- 恢复历史版本/快照/导入前：会先 `GET` 远端拿到**真实最新数据**并下载 `backup-before-<时间>.json`，避免“备份的其实是被覆盖前旧数据”。
- 数据超过约 1.5 MB 时，本机自动快照会跳过（避免占满浏览器存储），但远端保存仍会正常进行；请在数据菜单手动「导出备份 JSON」。

### 大文件与自动快照

- Gist 单文件建议控制在 **1 MB 以内**。GitHub API 对超过约 1 MB 的文件会截断内容，页面会尝试用 `raw_url` 拉全量，仍失败会报「数据文件过大/截断」并停止加载，避免用残缺数据覆盖远端。
- 保存时会压缩写入（不格式化），但商品/库存很多时仍可能接近上限；建议定期导出、清理回收站和不再使用的数据。

见前面「关于记住登录」（默认不勾选）。后台与扫码端凭据读写统一走 `ZCFI.credentials`，登录状态可通过同一浏览器的 local/session 凭据互通。

## 标签打印（CLodop）

打印使用 **C-Lodop** 打印控件（不是浏览器自带打印），需要先在电脑上安装并启动 C-Lodop。**仓库不再内置 `CLodopFuncs.js` 快照**，页面在运行时从本机 C-Lodop 加载官方脚本。

### 安装与启动

1. 安装 C-Lodop（从官方渠道下载安装包）。
2. 启动 C-Lodop 服务；Windows 任务栏应能看到 C-Lodop 图标。
3. 打开 `/admin`，顶部状态应显示「✅ 打印服务已就绪」；若显示未连接，按下面排查。

### 页面如何加载打印脚本

- **协议规则（v2.2.2 起）**：优先加载 `http://localhost:8000/CLodopFuncs.js`——浏览器把 `http://localhost` 视为可信来源，HTTPS 页面加载它**不构成混合内容**，同时可以绕开本机 C-Lodop 8443 可能**已过期**的证书；失败再试 `https://localhost.lodop.net:8443/CLodopFuncs.js`。
- **页面加载/登录时不会请求本机服务**（v2.2.2 起）：只有点「打印/系统预览」时才连接，避免一打开后台就弹出浏览器「访问本地网络/其他应用和服务」授权提示。首次打印时浏览器会询问，请选择「允许」。
- 本机 C-Lodop 的 8443 使用自签名证书，且**可能已经过期**（实测 `ERR_CERT_DATE_INVALID`）；页面优先用 `http://localhost:8000` 正是为了绕开它。若仍看到证书错误，请升级/重装 C-Lodop。
- 本机脚本只提供 `getCLodop()`（页面已补 `getLodop()` 别名）；**就绪判定要求 C-Lodop 的 WebSocket 真正连上**，而不是“脚本加载成功”。C-Lodop 内部用字符串定时器做握手/重连，页面已用定向垫片处理，因此**不需要放开 CSP 的 `'unsafe-eval'`**。
- 打印机列表来自**本机 C-Lodop 的实时列表**，不再使用作者本机的静态快照；换电脑/换打印机后会显示当前机器的设备。

### 打印结果以状态栏为准

- 打印/预览指令返回 `null` / `undefined` / `false` 一律视为**失败**并明确报错，不再“假成功”。
- 页面注册 C-Lodop 的 `On_Return` 回调，打印结果（成功/失败）以状态栏与提示为准。
- **未安装/未启动 C-Lodop 时**：仍可打开打印弹窗查看内置示意图；系统预览/直接打印会明确提示不可用，不会误报“已发送”。

### 编码文字（v2.3.2）

打印弹窗「编码文字」下拉，三选一（作用于所有模板，设置会记忆）：

| 选项 | 标签上显示 | 说明 |
| --- | --- | --- |
| 最后一级（默认） | `内部编码：001` | 内部编码只显示最后一级，便于人工核对 |
| 完整编码 | `内部编码：A001/B001/001` | 显示完整层级编码（超长会自动缩小字号保持单行） |
| 仅“内部编码” | `内部编码` | 不显示编码值，编码只在条码里 |

**v2.3.1 起预览与实际打印同源**：预览按与 LODOP 相同的 mm 坐标和 pt 字号排版；单行文字改用 LODOP 原生文本（字号精确，不再被 HTML 渲染放大裁断），PDF417 去掉旋转样式后正立；条码居中（实际 PDF417 墨迹居中，偏差实测 ≤0.2mm）。页面内预览的条码位置显示为「条码区域」占位框（实际条码由 C-Lodop/打印机生成）。

**v2.3.3 条码宽扁化**：40\*30 全系模板的 PDF417 高度改为 8.5mm（宽扁好扫）。

**v2.3.5 条码居中修复（真机）**：此前按“预估墨迹宽”反推条码对象左边界，对象框会超出纸张，真机驱动裁切/重锚定后表现为偏右、尺寸异常。现改为：先用真实 C-Lodop 预览标定**实测墨迹宽度**，再把**对象框宽设为该墨迹宽并水平居中**；所有打印项限制在 **2mm 打印安全区**内。

**v2.3.6 长编码修复**：PDF417 的墨迹宽会随编码长度跳档（实测 50\*30 默认 h14：18 字符 ≈38.6mm、29 字符 ≈45mm）。旧逻辑按“≤6 / ≤15 / >15”粗分档，29 字符仍按 39mm 对象框处理 → **墨迹溢出对象框**，真机裁切/重锚定后错位。现改为按“条码高度 + 编码长度锚点（4 / 18 / 29 / 48 字符实测）”自适应选对象宽（29 字符 → 46mm），并对每个长度样本做 2mm 安全区几何自检。用户复现的两条编码：`XICHA/HWD261113/XK`（18 字符）与 `XICHA/HWD261113/XK/261113/XY1`（29 字符）均已实测居中/不再溢出。

### 自定义文本（v2.3.3，仅“仅内部编码”模式）

当「编码文字」选择 **仅“内部编码”** 时，编码行左侧显示「内部编码」，右侧可打印自定义文本：

- 打印弹窗新增「自定义文本」输入框 + 字号（5/6/7/8pt，默认 6）；设置会记忆；
- 其他编码文字模式（最后一级 / 完整编码）不显示自定义文本；
- 长编码（如 29/43 字符）会让 PDF417 变宽并占用更多横向空间；40mm 纸对 >40 字符会明显偏窄，建议改用“最后一级编码”打印；
- 「内部编码」左对齐起点、自定义文本右边界均保持在 **2mm 打印安全区**内；
- 自定义文本**支持换行（多行）**，但区域底边不会低于「内部编码」所在行的底边（行高内自动排版）；
- 内容过长会先缩小到 5pt，仍放不下则截断并加省略号，不会折行/压边；
- 预览、打印、模板卡片三处一致。

### 打印步骤

1. 在商品/库存行点「打印标签」；节点可点「打印全部库存」；勾选多个库存可「批量打印」；勾选「全选当前筛选结果」后可**跨节点批量打印**。
2. 在打印弹窗选择：
   - 分类：先选「入库/出库」，再选模板（公共模板两类都有）；
   - 编码文字：最后一级 / 完整编码 / 仅“内部编码”；
   - 打印机：默认排除 PDF/虚拟打印机，优先真实打印机；也可手动切换；
   - 打印份数：1–100；
   - 「直接打印前先调用系统预览」：勾选后先打开 LODOP 预览。
3. 点「系统预览」或「直接打印」。
4. 打印前会**重新读取远端最新数据并按编码重新解析**：如果商品已被删除、改名或不存在，会中止/跳过并提示，避免打出旧标签。
5. **批量打印是 strict（全有或全无）**：只要有条目在复核时失效，会列出被跳过的条目并取消整批，不会“打一部分、假装都打了”。
6. 字段值为 `null` 时按空串处理（不会打出字符串 `null`）。
7. 已删除/回收站中的商品不能打印（会提示先恢复）。

### 打印设置记忆

模板、打印机、份数、「打印前先预览」会保存到本机（`zcfi_print_settings_v1`），下次打开自动恢复。若上次的打印机已不可用，会回落到默认打印机并提示。

### 份数 / 失败反馈

- 打印指令顺序为：`PRINT_INIT → SET_PRINT_PAGESIZE → SET_PRINT_COPIES → 内容 → PRINT/PREVIEW`，份数会按设置生效。
- 打印/预览失败（返回 falsy 或 `On_Return` 返回失败）会显示错误状态并 toast，不再静默失败。
- 未安装/未启动 C-Lodop 时：仍可打开打印弹窗查看**内置示意图**；系统预览/打印会提示不可用，不会误报成功。

### 打印失败排查

| 现象 | 处理 |
| --- | --- |
| 顶部显示「打印服务未连接」 | 启动 C-Lodop；确认没有被杀毒软件拦截 |
| 提示证书错误/无法加载 | 浏览器打开 `https://localhost.lodop.net:8443` 信任证书，再刷新 |
| 打开后台就弹出「访问本地网络/其他应用和服务」 | v2.2.2 起页面加载/登录时不再请求本机服务；该提示只应在点打印时出现，选「允许」即可 |
| 地址栏显示「不安全」或提示 8443 证书过期 | v2.2.2 起优先用 `http://localhost:8000` 绕开过期证书，且加载阶段不发起本机请求；仍出现请强制刷新（Ctrl+F5）并检查旧缓存/代理 |
| 控制台报 CSP 拦截 eval（C-Lodop 相关） | 页面已用定向垫片兼容 C-Lodop 的字符串定时器；若仍出现，请记录 C-Lodop 版本与报错 |
| 能预览但打印没反应 | 检查是否选择了真实打印机；查看 C-Lodop 打印队列/日志；再看状态栏的 `On_Return` 结果 |
| 标签内容错位/字体不对 | 与打印机驱动、纸张尺寸（50×30 或 40×30mm）、C-Lodop 版本有关；需现场调 |
| 份数不对/重复打印 | 已按 `SET_PRINT_COPIES` 顺序修复；如仍不对，请记录模板/纸张/驱动并现场验证 |
| 打印前提示数据已变更 | 有其它设备删除/改名了商品；按提示刷新后台后重新打印 |

> ⚠️ 打印效果与打印机型号、驱动、纸张、C-Lodop 版本强相关。**真实打印必须在现场用实际打印机验证**，内置预览只能作为版式参考。

## 备份与恢复

详细步骤见 [备份与恢复](docs/BACKUP-AND-RECOVERY.md)。记住四层备份：

| 层 | 位置 | 保留 | 恢复方式 |
| --- | --- | --- | --- |
| GitHub Gist 历史版本 | GitHub Gist 自身 | GitHub 保留的历史 | 管理后台「数据 → 历史版本」或 Gist 网页 Revisions |
| 后台自动本地快照 | 本机浏览器 localStorage（按 Gist ID 隔离） | 最多 3 份（每次保存前） | 管理后台「数据 → 本地快照」 |
| 手动导出 JSON | 你的电脑下载目录 | 由你保管 | 管理后台「数据 → 导入 JSON」 |
| 扫码历史 | 本机浏览器 localStorage（按 Gist ID 隔离） | 最近 200 条 | 页面内查看/撤销清空（不是商品数据备份） |

> **本地导出的 JSON 才是最终保障**：Gist 一旦被删除，没有可自助恢复的回收站（见下文）。

恢复/导入前，系统会**先从远端拉取最新数据并下载 `backup-before-*.json`**，再二次确认覆盖；即使点错，也能用这份备份找回被覆盖的内容。

代码回滚（维护者）：见 [发布检查清单](docs/RELEASE-CHECKLIST.md) 与 [备份与恢复](docs/BACKUP-AND-RECOVERY.md)。本地备份目录：`local_dev/backups/`（该目录不参与站点发布，也不提交仓库）。

常用回滚命令（维护者，**在仓库根目录执行**；执行前先确认 `git status` 没有未备份改动）：

```powershell
# 在仓库根目录执行：先确认工作区
git status

# 1) 备份当前文件
Copy-Item scan.html "local_dev\backups\$(Get-Date -Format yyyyMMdd-HHmmss)-before-rollback-scan.html"

# 2) 只回滚某个文件到历史 tag（不删除其它改动）
git checkout backup-r3 -- admin.html
git checkout backup-scan-fix -- scan.html
git checkout backup-r1-core21 -- js/core.js

# 3) 整库回滚（危险：会丢弃未提交改动）
# git status
# git reset --hard backup-r3
```

已使用的标签：`backup-r0`、`backup-r1`、`backup-r1-admin`、`backup-r1-core21`、`backup-r2a`、`backup-r2-scan`、`backup-r2b`、`backup-scan-fix`、`backup-r3`、`backup-docs`；本次发布的备份 tag 由维护者按发布流程补充。tag 与备份目录 `local_dev/` 不参与站点发布；发布时按发布检查清单确认备份 tag 已推送。

**建议**：每周至少手动导出一次 JSON；每次批量导入/批量删除前先导出；Token 到期/换新前先导出。

## 安全与隐私

- **Token 只在你的浏览器**：页面用 Token 直接请求 GitHub API，不经过任何中间服务器；Token 只出现在 `Authorization` 请求头。
- **数据只在你的 Gist**：页面不会把商品数据发到 GitHub 以外的地方；图片识别完全在本机。
- **XSS 防护**：页面所有来自 Gist / 扫码内容的文本都按纯文本转义渲染（后台和扫码端均已处理）。
- **Secret Gist 不是私有**：Secret 只是不公开列出，链接即权限；公开 Gist 的地址更可能被搜索引擎/他人发现。写入仍需 Token，但**读取不需要**。
- **Token 权限**：只给 Gist 读写，不要给仓库/组织权限；定期轮换；`gists` 权限是账号级，泄露 = 全部 Gist 可读写。
- **共用电脑**：默认不勾选「记住登录」；使用后退出登录（可同时清理本机历史）；共用设备可在浏览器设置中清除站点数据。
- **备份**：任何自动化都不能替代你自己的导出备份。遇到不确定的操作，先导出。

### 信任边界清单

| 目的地 | 何时访问 | 能接触到什么 | 风险与说明 |
| --- | --- | --- | --- |
| `api.github.com` | 登录、读取、保存、历史版本 | Token（**只在 `Authorization` 头**）、Gist 内容 | GitHub 官方 API；Token 不进 URL/Gist/日志。Token 泄露即可读写该账号**全部** Gist |
| `gist.githubusercontent.com` | 大文件（>1 MB）时 `raw_url` 回退读取 | 公开/Secret Gist 的 raw 内容 | 无 Token 也可读取；Secret Gist 的 raw 链接同样无需登录 |
| `https://localhost.lodop.net:8443`、`http://localhost:8000` | 打印时加载本机 C-Lodop 脚本、发送标签数据 | 打印标签内容（商品名、编码、单号等） | **本机** C-Lodop 服务，运行时加载的第三方脚本通道；自签证书需手动信任。只应在本机使用，不要在不可信网络暴露该端口 |
| CDN（原第三方脚本源） | — | — | **已移除**：`html5-qrcode` 自托管到 `js/vendor/`，站点不再从 CDN 加载任何脚本 |

补充说明：

- `gists` 权限是**账号级**的：Token 泄露 = 攻击者可读写该账号下所有 Gist。建议用专用账号、最小权限、定期轮换。
- **CSP 现状**：`index.html` 与 `tools/scanner-test.html` 已加 `<meta http-equiv="Content-Security-Policy">` 与 `Referrer-Policy: no-referrer`；`admin.html` / `scan.html` 的 CSP 仍包含 `'unsafe-inline'`（因为页面是单文件内联脚本）。要收紧到严格 CSP，需要先把内联脚本/样式外置——这是后续项，不是当前状态。
- 站点无后端、无服务端鉴权：拿到同一 Token + Gist ID 的人即可读写；团队使用需自行管理 Token 与 Gist 可见性。

## 已知限制

- **Secret Gist 非私有**：链接即权限，无法阻止拿到链接的人读取；敏感数据不应放 Gist。
- **本机 C-Lodop 的 8443 证书可能已过期**（`ERR_CERT_DATE_INVALID`）：页面已改为优先 `http://localhost:8000` 绕开它；若两个地址都失败，请升级/重装 C-Lodop。
- **浏览器「访问本地网络」授权**：v2.2.2 起页面加载/登录时不再请求本机服务，只有点打印时才会出现该授权提示，选择「允许」即可。
- **真实打印需现场验收**：内置 canvas 预览只是示意图；纸张/打印机/驱动/C-Lodop 版本不同，实际效果以现场打印为准；**打印必须在本机安装并启动 C-Lodop**。
- **没有 Service Worker/PWA 离线包**：页面需先打开；断网时可用缓存继续匹配，但保存需要联网。
- **Gist 单文件约 1 MB 限制**：超大商品库需精简数据或拆分使用；超过约 1.5 MB 时本机自动快照会跳过。
- **无多用户权限模型**：没有账号体系与角色；共用同一 Token + Gist 的人都能读写，靠冲突检测和团队约定。
- **内联脚本导致 CSP 需 `'unsafe-inline'`**：`admin.html`/`scan.html` 尚未外置脚本，严格 CSP 是后续项。
- **编码大小写/旧数据**：后台导入/体检会提示大小写规范与重复编码；仍建议统一大写、不要手工制造大小写差异。
- **扫码历史只在本机**：不跨设备同步、不写 Gist；换手机/清浏览器会丢失。
- **非命中节点保留 DOM**：搜索时未命中的节点可能仍在 DOM 中（用隐藏 class 控制显示）以保证展开/滚动性能；大数据量下内存占用会随节点数增长。

## 部署与更新

- 站点通过 **GitHub Pages** 发布：仓库 `main` 分支的静态文件自动上线，无需构建。
- 自定义域名：`CNAME` 文件内容为 `xypipei.zcfi.cn`；DNS 需配置到 GitHub Pages。
- 路由：站点根路径 `/` 为导航页，`/admin` → `admin.html`，`/scan` → `scan.html`。
- 更新：修改并推送到 `main` 后，通常 1–3 分钟生效；强缓存时可强制刷新（Ctrl/Cmd+Shift+R）。
- 依赖：
  - `js/core.js`：共享数据层（本地文件，v2.2.0）
  - `js/vendor/html5-qrcode.min.js`：扫码库（自托管，锁 `2.3.8`，无 CDN 依赖；来源与 SHA-256 见 `js/vendor/README.md`，CI 校验哈希）

- 校验：`node tools/verify.mjs`（静态/语法/文档一致性），CI 见 `.github/workflows/ci.yml`。
- 改动上线前请走 [发布检查清单](docs/RELEASE-CHECKLIST.md)。

## 常见问题速查

| 问题 | 快速处理 |
| --- | --- |
| 登录 401 / Token 无效 | Token 过期/权限不足/复制错；重新生成只勾 Gist 权限的 Token |
| 登录 403 | 先看是不是 **限流**（等几分钟再试），再确认 Token 有 `gist` 权限 |
| 登录 404 / 找不到文件 | Gist ID 错、文件名不是 `data.json`、或 Gist 被删；无 `gist` 权限的 Token 也可能返回 404 |
| 登录页 Gist ID 是空的 | 正常：默认值已移除，必须填写你自己的 Gist ID |
| 提示数据文件过大/截断 | 清理回收站/无用数据，导出后精简；保持 data.json < 1 MB |
| 冲突弹窗怎么选 | 逐字段选择「用我的」或「用远端」；不确定时先用远端，再重新编辑 |
| 页面「版本：未知」 | Gist 历史接口暂不可用/权限不足；不影响数据读写 |
| 回收站找不到商品 | 在「数据 → 回收站」；注意父节点删除时整棵子树都在回收站 |
| 摄像头打不开 | HTTPS、浏览器允许摄像头、不要用内嵌微信/QQ 浏览器；iOS 需 Safari ≥ 15.1 |
| 扫码没反应/对不上 | 用「图片识别」或手动输入；检查标签是否旧编码（改名后旧标签失效） |
| 手电筒不显示 | 设备/浏览器不支持 torch 能力，属正常降级 |
| 打印服务未连接 | 安装并启动 C-Lodop；HTTPS 需信任本机证书；看状态栏错误提示 |
| 打印提示失败/没出纸 | 以状态栏 `On_Return` 结果为准；检查打印机是否真实设备、C-Lodop 队列 |
| 份数不准/内容错位 | 份数顺序已修复（`SET_PRINT_COPIES` 在 `PRINT_INIT` 之后）；仍不对请现场记录模板/纸张/驱动 |
| 打印前提示数据已变更 | 打印前会读取远端并复核编码；有删除/改名/不存在会中止或跳过，按提示刷新后重打 |
| 编码大小写/重复 | 导入/体检会提示大小写规范与重复编码；建议统一大写，避免扫码歧义 |
| scan 自动登录/换账号 | 默认不记住登录；退出清两处凭据（可选清历史）；旧账号先两页退出再登录 |
| 历史记录显示「已删除」 | 该商品已在回收站/不存在；点击会被拦截，去后台回收站恢复后再扫 |
| 怎么强制刷新远端数据 | 点顶部 ⟳；或刷新页面/重新登录；保存前本来就会重新 GET 远端 |
| 清空历史后悔了 | 12 秒内点底部「撤销」（保留最近 20 条） |
| `/` 打不开/该进哪 | `/` 是导航页；管理后台 `/admin`，手机扫码 `/scan` |

更多见 [FAQ](docs/FAQ.md)。
