# 备份与恢复

数据只保存在 **GitHub Gist**，但「Gist 里有数据」不等于「数据一定安全」：误删、误导入、冲突覆盖、Token 丢失都可能出问题。请按下面的层次做备份。

> **最重要的一条**：**本地导出的 JSON 才是最终保障**。GitHub 没有面向用户的 Gist 回收站——Gist 一旦被删除，**无法自助恢复**，只能联系 GitHub Support，且不保证能找回。任何页面内备份都不能替代你自己的导出文件。

---

## 1. 备份分几层

| 层 | 存在哪里 | 保留多久 | 谁负责 | 适合场景 |
| --- | --- | --- | --- | --- |
| ① GitHub Gist 历史版本 | GitHub Gist 自身（`history`） | GitHub 保留的版本历史 | 自动 | 误保存、需要回滚到某个时间点（**注意：Gist 删除时历史版本一并消失**） |
| ② 后台自动本地快照 | 浏览器 `localStorage`（键 `zcfi_admin_snapshots_v1`，按 Gist ID 隔离） | 最多 3 份（每次保存前） | 自动 | 刚刚保存错了，快速回退 |
| ③ 手动导出 JSON | 你的电脑下载目录/网盘/移动硬盘 | 你自己保管 | 手动 | **长期备份、换电脑、Gist 被删后的唯一恢复来源** |
| ④ 扫码历史 | 浏览器 `localStorage`（键 `zcfi_scan_history_v1`，按 Gist ID 隔离） | 最近 200 条 | 自动（仅本机） | 查刚才扫了什么，不是商品数据备份 |
| ⑤ 代码/页面备份 | 本地 git 仓库 + 远端 tag | 手动 | 维护者 | 页面改坏、需要回滚到旧版本 |

> **Gist 是最终数据源，但它本身也会丢**：只有 ③ 完全由你控制。建议每周至少做一次 ③，并放到与电脑不同的位置。

## 2. 普通用户：数据备份与恢复

### 2.1 手动导出备份（最推荐）

后台 `/admin`：

1. 点「🗄 数据」→「⬇️ 导出备份 JSON」。
2. 浏览器下载 `zcfi-backup-<时间>-manual.json`。
3. 把文件存到网盘/移动硬盘等**另一处**。

建议时机：

- 每周一次；
- 批量导入/批量删除/批量改状态前；
- 改名/改编码前；
- 换 Token / 换电脑 / 删除 Gist 前。

### 2.2 导入 JSON 恢复

1. 后台 →「🗄 数据」→「⬆️ 导入 JSON…」。
2. 选择备份文件。
3. 页面会显示节点/库存数量与体检结果；有结构错误（errors）会禁止导入。
4. 勾选确认「导入将替换当前全部数据」。
5. 点「下载当前备份并导入」——导入前会**先 `GET` 远端真实最新数据并下载 `backup-before-<时间>.json`**，再执行导入。

注意：

- 导入是用备份文件里的 `products` **替换**当前全部商品数据（根级其它字段与 `schemaVersion` 按恢复内容处理，未知根字段保留）。
- 导入的备份里如果包含回收站条目，也会一起恢复。
- **恢复/导入会覆盖远端**：如果其他设备刚写入过修改，页面会提示远端有会丢失的改动并二次确认；被覆盖的内容可从刚下载的 `backup-before-*.json` 找回。
- 导入后如果发现不对，可立即用「本地快照」或 Gist 历史版本回到导入前。

### 2.3 本地自动快照

- 每次在后台保存前，页面会自动把当前数据存到本机（最多 3 份）。
- 快照**按 Gist ID 隔离**：不同账号/不同 Gist 的快照互不可见；退出登录时会清理非当前 Gist 的快照。
- 后台 →「🗄 数据」→「🧷 恢复本地快照…」可选择一份恢复。
- 恢复前会先自动从远端拉取并下载当前数据备份（`backup-before-*.json`）。
- 数据超过约 1.5 MB 时，为节省浏览器存储会跳过自动快照（远端保存不受影响），请手动导出。
- 换浏览器/清理站点数据会丢失快照。

### 2.4 Gist 历史版本恢复

后台 →「🗄 数据」→「🕘 历史版本…」：

1. 选择要查看的提交版本。
2. 查看节点/库存统计与字段差异概览。
3. 点「恢复此版本…」确认（按提示输入 `RESTORE`）。
4. 恢复前会先自动从远端拉取最新数据并下载 `backup-before-<时间>.json`；若远端有并发修改，会二次确认。
5. 恢复只替换 `products`（及 `schemaVersion`），根级其它字段保留。

也可以在 GitHub Gist 网页的 **Revisions** 里查看历史（更底层，不推荐普通用户直接改）。

> GitHub 只保留一定期限的 Gist 历史；具体保留策略以 GitHub 官方为准，不能当作长期备份。

### 2.5 扫码历史与本地偏好

- 扫码历史只在本机，不是商品数据；**按 Gist ID 隔离**，退出登录时可选择一并清除。
- 「更多 → 清空历史」需确认；清空后 12 秒内可撤销（保留最近 20 条），撤销窗口结束/成功后备份会被删除。
- 换手机/清理浏览器会丢失，且不同步。
- 视图状态（`zcfi_admin_view_v1`）、打印设置（`zcfi_print_settings_v1`）、scan 设置（`zcfi_scan_settings_v1`）也是本机偏好，不在 Gist 中；清理浏览器后需要重新设置。

## 3. 误操作场景怎么救

| 场景 | 首选恢复方式 |
| --- | --- |
| 刚在后台保存错了 | 「🧷 恢复本地快照」（最近 3 份） |
| 批量导入错文件 | 「🕘 历史版本」回到导入前；导入时自动下载的 `backup-before-*.json` 也可用 |
| 误删商品 | 「🗑️ 回收站」恢复；父节点还在回收站时先恢复父节点 |
| 彻底删除错了 | 用导出备份/Gist 历史版本恢复；本地快照也可能有 |
| 改编码后发现旧标签失效 | 改回编码（会级联）或重新打印；无法扫到旧编码时先恢复编码 |
| Token 泄露/丢失 | GitHub 撤销旧 Token、生成新 Token；数据不受影响，重新登录即可 |
| **Gist 被误删** | **无法自助恢复**：GitHub 没有面向用户的 Gist 回收站；只能立即**联系 GitHub Support** 尝试找回（不保证），恢复成功与否取决于官方。**因此本地导出的 JSON 才是最终保障**——有导出就重新建 Gist 导入；没有导出则可能永久丢失 |
| 页面打不开/版本未知 | 先确认网络与 GitHub 状态；数据在 Gist 里，不会因页面坏而丢 |

## 4. 维护者：代码与页面回滚

> 以下命令只给维护者使用，**在仓库根目录执行**（用相对路径，不要硬编码本机绝对路径）。
> 参考 `README.md` 与 `docs/RELEASE-CHECKLIST.md`。

### 4.1 本地备份目录

- `local_dev/backups/`：本地备份目录（已被 `.gitignore` 忽略，不参与站点发布，也不提交仓库）。
- 命名约定：`<时间戳>-<阶段>-<文件>`，例如：

  ```
  local_dev/backups/20261021-134037-baseline/
  local_dev/backups/20261021-181455-r2-before-scan.html
  ```

- 每轮改动前建议复制当前文件（在仓库根目录执行）：

  ```powershell
  Copy-Item scan.html "local_dev\backups\$(Get-Date -Format yyyyMMdd-HHmmss)-rN-before-scan.html"
  ```

### 4.2 git 标签

当前本地标签：

| 标签 | 含义 |
| --- | --- |
| `backup-r0` | 原始基线 |
| `backup-r1` | R1 数据安全重构完成 |
| `backup-r1-admin` | 后台 R1 |
| `backup-r1-core21` | 核心 2.1.0 |
| `backup-r2a` | 后台 R2a |
| `backup-r2-scan` | 扫码端 R2 |
| `backup-r2b` | 后台 R2b（搜索/排序/汇总/复制/批量/响应式） |
| `backup-scan-fix` | 扫码端一致性修复（凭据/历史已删除标记） |
| `backup-r3` | 后台 R3 打印 v2 + 一致性修复 |
| `backup-docs` | 文档终稿（README/CHANGELOG/docs） |
| 本次 v2.2.0 标签 | 由发布流程创建；发布检查清单要求确认**备份 tag 已推送** |

查看（在仓库根目录执行）：

```powershell
git tag --list
git log --oneline -10
```

### 4.3 只回滚某几个文件（推荐）

在仓库根目录执行：

```powershell
git status
git checkout backup-r3 -- admin.html
# 或
git checkout backup-scan-fix -- scan.html
# 核心
git checkout backup-r1-core21 -- js/core.js
```

先确认目标文件的当前改动已备份/提交，避免覆盖未保存工作。

### 4.4 整库回滚（危险）

在仓库根目录执行：

```powershell
git status                 # 先确认没有未提交的重要改动
git log --oneline -5       # 确认目标提交
git reset --hard backup-r3
```

- `reset --hard` 会丢弃当前未提交改动，**执行前务必确认**。
- 如果只想看旧版本而不改动工作区：

  ```powershell
  git show backup-r3:admin.html | Out-File -Encoding utf8 "local_dev\backups\admin-r3-history.html"
  ```

### 4.5 回滚后检查

1. 页面能正常登录、加载数据。
2. 后台/扫码端关键流程各走一遍（见发布检查清单）。
3. 文档版本号与代码一致（`core v2.2.0` / `admin R4` / `scan R3`）。
4. 确认没有把 Token、Gist 内容、`local_dev/` 提交进仓库。

## 5. 恢复后的验证清单

- [ ] 后台能登录，商品树/搜索/回收站正常
- [ ] 关键商品字段（名称/状态/成本/快递/订单/链接/备注）正确
- [ ] 扫码端能扫到商品并打开详情
- [ ] 关联一次快递/订单/链接，确认保存成功
- [ ] 导出一次 JSON，确认文件能打开
- [ ] 打印预览能打开（真实打印另需现场验证）

> 任何恢复操作前，先「导出备份 JSON」；任何批量操作前，也先导出。**Gist 删除不可自助恢复，导出文件是你最后的退路。**
