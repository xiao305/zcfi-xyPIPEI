# 用户手册（管理后台 + 扫码端）

本手册面向**最终用户**，照着做即可完成首次配置和日常操作。
不想看长文？先看 [README 的首次使用](../README.md#首次使用5-步)，再回来查细节。
版本基线：v2.2.0（2026-11-13）。

---

## 1. 开始前需要准备什么

| 准备项 | 说明 |
| --- | --- |
| GitHub 账号 | 数据存在 GitHub Gist 里，必须有账号 |
| 一个 Gist（数据文件） | 文件名固定建议 `data.json`，内容先写 `{"schemaVersion":1,"products":{}}` |
| GitHub Token | 只给 Gist 读写权限；只显示一次，务必保存 |
| 一个浏览器 | 电脑用 Chrome/Edge；手机用 Safari/Chrome。手机扫码需 HTTPS 和摄像头权限 |
| C-Lodop（只打印需要） | 安装在本机电脑并保持运行 |

> **安全前提**：GitHub 的 Secret Gist **不是私有仓库**，拿到链接的人无需登录就能读取。**不要把成本、订单号、快递单号等敏感数据**放在可能被分享/猜到的 Gist 里。

### 1.1 创建数据 Gist

1. 登录 <https://gist.github.com>。
2. 文件名：`data.json`。
3. 内容：`{"schemaVersion":1,"products":{}}`（先建空库，后面用后台加商品）。
4. 点「Create secret gist」（至少不会被公开列出；但请记住 **Secret 不是私有**）。
5. 创建后，浏览器地址类似：

   ```
   https://gist.github.com/你的用户名/<你的GistID>
   ```

   最后一段 `<你的GistID>` 就是 **Gist ID**，复制保存。
   登录框里**没有默认值**，必须填写你自己的 Gist ID。

### 1.2 创建 GitHub Token

推荐 Fine-grained token：

1. GitHub 右上角头像 → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token。
2. Token name 随便填（例如 `zcfi-scan`），Expiration 按需。
3. 权限只勾 **Gists: Read and write**。其它权限一律不给。
4. Generate → 复制 Token（`github_pat_...` 或 `ghp_...`）。

> - Classic token 也可以，但**只勾 `gist`**。
> - Token 只保存在本机浏览器，随请求通过 `Authorization` 头发给 `api.github.com`（这是 GitHub API 必需）；不会发给其它域名。
> - `gists` 权限是**账号级**的：Token 泄露 = 该账号下所有 Gist 可读写。建议专用账号 + 定期轮换。
> - 不要把 Token 发给任何人，不要贴到聊天、截图、Issue、代码里。怀疑泄露立即 Revoke。

### 1.3 登录

打开管理后台或扫码端，填写 Token / Gist ID / 文件名 → 登录。

- **Gist ID 默认空**：必须填写自己的，留空不能登录。
- 「记住登录（本机）」**默认不勾选**：不勾选只在本次会话有效；勾选后 Token 会留在本机浏览器（共用设备不要勾选）。
- 失败时先看错误提示：401 多半是 Token；403 先看是不是限流；404 看 Gist ID、文件名，也可能是 Token 没有 gist 权限。
- 更多错误见 [FAQ](FAQ.md)。

### 1.4 入口说明

- 站点根路径 `/` 是**导航页**（不是扫码测试页），提供两个入口：
  - 「进入管理后台」→ `/admin`
  - 「手机扫码」→ `/scan`
- 扫码库调试页 `tools/scanner-test.html` 仅供开发调试，日常不用。

## 2. 管理后台 `/admin`

### 2.1 页面布局

- 顶部：登录状态/最后同步时间/数据版本/打印服务状态；添加大类、刷新、数据菜单、退出。
- 汇总条：节点/库存/在售/售出/待售数量；每个节点行也有子类/库存/状态汇总。
- 筛选栏：按大类筛选、节点排序、搜索框（编码/名称/单号/备注/状态/链接，防抖+高亮）。
- 商品树：每个节点显示名称、编码、类目条码、状态、订单号；节点下可展开子类和库存表。
- 回收站/数据工具：在「🗄 数据」菜单里。

### 2.2 建商品树

1. **添加大类**：顶部「＋ 添加大类」。
   - 名称必填。
   - 编码默认自动生成 `A001`、`A002`……，一般不用改。
2. **添加子类**：在「类目条码=是」的节点行点「添加子类」，生成 `A001/B001`。
3. **添加库存**：在「类目条码=否」的节点行点「添加库存」，生成 `A001/B001/001`。
   - 弹窗里的「添加数量」可填 1–100：一次批量生成连续编码的 N 件库存（如 001、002、003）。
4. 每个库存是独立的一件商品，可单独设置成本、快递、订单、状态、备注。

> 「类目条码」含义：是=该节点下继续加子类；否=该节点下加库存。已有数据按原设置使用，不建议随意切换后混用。

### 2.3 编辑 / 复制节点与库存

点行内「编辑」：

| 字段 | 说明 |
| --- | --- |
| 名称 | 必填 |
| 编码 | 默认只读；高级用户可勾「自定义编码」手填，必须符合格式且全局唯一 |
| 类目条码 | 是=该节点下继续加子类；否=该节点下加库存（原“统一条码”） |
| 状态 | 待售 / 在售 / 售出 |
| 成本 | 数字，可空 |
| 快递单号 | 手填或扫码关联写入 |
| 订单号 | 手填或扫码关联写入 |
| 链接 | 多个链接用英文/中文逗号或换行分隔 |
| 备注 | 任意文本 |

保存时：
- 只提交实际修改的字段，不会整库覆盖。
- 如其它设备同时改了同一字段，会弹出冲突窗，逐项选择「用我的」或「用远端」。
- 正在保存时其它按钮会暂时不可用，避免重复提交。

其他行内操作：
- 「复制」：复制节点/库存字段生成副本（节点名加「（副本）」），编码自动生成；复制嵌套节点会放在**正确的父节点**下。
- 「复制编码」：把编码复制到剪贴板。

### 2.4 编码规则（重要）

| 层级 | 格式 | 示例 |
| --- | --- | --- |
| 大类 | `A` + 三位数字 | `A001` |
| 子类 | 父编码 + `/B` + 三位数字 | `A001/B001` |
| 库存 | 父编码 + `/` + 三位数字 | `A001/B001/001` |

- 节点与库存编码**全局唯一**（包括回收站中的，彻底删除后才释放）。
- 改名会级联更新下级编码；**旧标签/旧二维码会失效**，需要重新打印。
- 不建议手工输入带空格、大小写混杂的编码；扫码端归一（去掉零宽字符与所有空白，含全角空格）并忽略大小写匹配。
- 导入/数据体检会检查编码大小写重复（errors 阻止导入）并提示非大写编码；建议统一大写。
- 恢复子节点前必须先恢复父节点（上级在回收站时不允许恢复子项）。

### 2.5 搜索 / 排序 / 汇总 / 批量（R2b，R4 修复）

- 搜索：输入后约 200ms 自动搜索（也可回车立即搜索），支持编码、名称、订单号、快递单号、备注、状态、链接；命中文字高亮；**中文输入法组合期间不会触发重渲染**。
- 排序：
  - 节点可按编码/名称/更新时间升降序；
  - 库存表头可点击按编码/名称/成本/快递单号/订单号/状态排序。
- 汇总：顶部汇总条 + 节点行汇总（子类/库存/在售/售出/待售）；**已删除父节点下的子库存不计入汇总**。
- 按大类筛选：会显示该大类下的子类与全部库存（不会只剩一个空大类行）。
- 视图记忆：搜索词、筛选、排序、展开状态会保存在本机，刷新后恢复。
- 勾选库存后：
  - 节点内「批量打印」「批量修改状态」；
  - 勾选「全选当前筛选结果」后，可「跨节点批量改状态」「跨节点批量打印」。
- 快捷键：`Ctrl/Cmd+F` 搜索、`Ctrl/Cmd+S` 保存当前编辑弹窗、`Enter` 弹窗内保存、`Esc` 关闭弹窗/菜单。
- 响应式：窄屏/390px 下自动换行、弹窗全屏、按钮 44px；宽库存表可横向滚动。
- 已删除（回收站）的项不会出现在搜索/排序/汇总/打印中。

### 2.6 删除与回收站

- 行内「删除」→ 输入编码确认 → **移入回收站**（软删除，数据还在 Gist）。
- 回收站里可：
  - **恢复**：恢复节点/库存；如果父节点还在回收站，必须先恢复父节点。
  - **彻底删除**：永久移除，不可恢复；节点会连同其子类和库存一起删除。
- 删除父节点时整棵子树都会被隐藏；恢复父节点后子项重新可见。
- 彻底删除会释放编码，之后可重新使用该编码。

### 2.7 数据菜单（导出/导入/体检/历史/快照）

| 菜单 | 使用场景 | 注意 |
| --- | --- | --- |
| 导出备份 JSON | 定期备份、改数据前备份 | 文件保存到你电脑；**这是最终保障** |
| 导入 JSON | 换电脑/恢复备份 | **会替换当前全部商品数据**；导入前自动从远端拉取并下载当前备份；结构错误会禁止导入 |
| 数据体检 | 数据异常/导入前检查 | 统计节点/库存/回收站，列出 errors/warnings |
| 历史版本 | 误操作后回滚 | 查看 Gist 提交版本与差异，恢复前自动从远端拉取并下载备份；恢复是整库替换 |
| 本地快照 | 最近几次保存的快速回退 | 每次保存前自动记录，最多 3 份，按 Gist ID 隔离；超过 1.5MB 会跳过 |
| 回收站 | 恢复误删 | 见上 |

> **恢复/导入会覆盖远端**：系统会先从远端拉取真实最新数据并下载 `backup-before-<时间>.json`，再弹二次确认。即使点错，也能用这份备份找回被覆盖的内容。

### 2.8 记住登录 / 退出

- 「记住登录（本机）」**默认不勾选**：不勾选时 Token 只保存到 `sessionStorage`，关闭浏览器/标签页后失效。
- 勾选：Token 保存到 `localStorage`，下次打开自动登录；**共用电脑不要勾选**。
- 「退出」会清理本机保存的凭据（同时清理 local/session 两处）；扫码端退出还可同时清理本机历史。
- 共用电脑建议取消勾选，用完退出；必要时在浏览器里清除本站点数据。

## 3. 扫码端 `/scan`

### 3.1 登录与摄像头

1. 打开 `/scan`（手机浏览器），填写 Token/Gist ID/文件名（**Gist ID 默认空，必须填自己的**）。
2. 「记住登录（本机）」**默认不勾选**：不勾选 → `sessionStorage`，关闭标签页/浏览器后失效；勾选 → `localStorage`，关闭浏览器仍自动登录。退出会清理两处。
3. 点「开始扫码」，浏览器询问摄像头权限 → 允许。
4. 摄像头画面出现后，把二维码/条形码/PDF417 放入取景框。
5. 识别成功会有短震动/提示音（设置可关）。

> 手机必须用 HTTPS；iOS Safari 需要较新版本；微信/QQ 内置浏览器可能限制摄像头，建议用系统浏览器打开。

### 3.2 扫码后

- 命中 1 个商品：底部抽屉显示详情。
- 命中多个（同一订单号/快递号重复）：
  - 弹出候选列表，顶部黄条提示「该单号命中 N 个商品，请确认」。
  - 点选正确的一项进入详情。
- 未命中：弹窗提示；点「继续扫描」回到扫码；也可查看历史。
- 命中已删除商品：提示「该商品已删除，请到后台回收站恢复」，不会进详情。

### 3.3 连续模式

- 顶部「连续模式」默认开启：
  - 命中商品后摄像头保持开启，只暂停解码回调；
  - 关闭详情抽屉后直接继续扫，不需要重新点开始；
  - 未找到弹窗点「继续扫描」、关联成功点「继续扫下一件」也都不重启摄像头。
- 关闭「连续模式」：每次扫码后会停止摄像头，需手动点「开始扫码」。设置保存在本机。

### 3.4 关联快递/订单/链接

1. 打开商品详情 → 点「扫描关联信息」。
2. 扫描或手动输入要关联的内容：
   - 以 `http://` / `https://` 开头 → 链接
   - 符合常见快递单号格式 → 快递单号
   - 其它 10 位以上纯数字 → 订单号
3. 在关联确认弹窗可手动改类型；如果商品已有同类型值，会提示替换/已绑定。
4. 可勾选「关联后标记为售出」。
5. 点「确认关联」：
   - 成功：详情更新，出现「继续扫下一件」。
   - 失败：保留在弹窗里，提示错误，可点「重试保存」。
   - 如果后台同时改了同一字段：弹**逐字段冲突**选择（基准/远端/我的），不会一键整体覆盖。

### 3.5 图片识别

1. 点「图片识别」。
2. 从相册/文件选择二维码截图。
3. 图片只在本机解码，识别结果走与摄像头相同的查询流程。
4. 失败时换清晰图片。

### 3.6 历史

- 历史按日期分组，点记录可回看商品；历史**按 Gist ID 隔离**，换账号/换 Gist 不串数据。
- 如果历史对应商品已被删除（或已不存在），该条会置灰并显示灰色「已删除」徽章；点击仍提示「该商品已删除，请到后台回收站恢复」，不会打开详情。无 ref 的旧记录不显示徽章。
- 「更多 → 清空历史」需确认；清空后 12 秒内底部「撤销」可恢复最近 20 条（撤销窗口结束后备份删除）。
- 历史只在本机，不占 Gist；退出登录时可选择一并清除本机历史。

### 3.7 数据刷新/离线

- 顶部显示「数据更新于 HH:mm」，点 ⟳ 手动刷新。
- 后台每 30 秒自动刷新；页面重新可见时也会刷新。
- **只有网络问题会显示离线**（断网/限流/服务异常），此时仍可用缓存匹配；保存时会重新联网，失败可重试。
- Token 失效（401）会要求重新登录；数据损坏（`PARSE`/`SCHEMA`/`TRUNCATED`）会明确报错并禁止保存，避免覆盖远端。

### 3.8 设置

「更多 → 设置」：

- 连续扫码模式（与顶部开关同步）
- 扫码成功震动
- 扫码成功提示音

设置保存在本机浏览器。

## 4. 标签打印（管理后台，打印 v2）

### 4.1 前置条件

1. 在电脑**安装并启动 C-Lodop**（任务栏应有图标）。
2. **信任本机证书**：浏览器新开 `https://localhost.lodop.net:8443`，选择「继续访问/信任证书」。
3. 打开 `/admin`，顶部状态应显示「✅ 打印服务已就绪」。
4. 页面运行时从本机加载 `CLodopFuncs.js`（`https://localhost.lodop.net:8443` 或 `http://localhost:8000`），仓库不再内置该脚本；打印机列表来自**当前机器的真实打印机**。

### 4.2 打印结果以状态栏为准

- 点「系统预览」或「直接打印」后，**是否成功看状态栏与提示**（页面注册了 C-Lodop 的 `On_Return`）。
- 失败提示的含义：
  - 「打印服务未连接/不可用」：C-Lodop 没装/没启动，或证书未信任；
  - 「打印指令未发送」：脚本加载失败或服务断开；
  - 「打印失败：C-Lodop/打印机返回失败」：打印机离线、驱动异常、纸张/名称不符；
  - 「N/M 已失效，已取消」：批量打印 strict 复核发现条目被删除/改名，整批取消。
- **不会再出现“提示已发送但一张没出”的假成功**。

### 4.3 打印入口与弹窗

1. 打印入口：
   - 商品/库存行「打印标签」；
   - 节点「打印全部库存」；
   - 勾选多个库存「批量打印」；
   - 勾选「全选当前筛选结果」后「跨节点批量打印」。
2. 打印弹窗：
   - **3 套模板**：`50*30 内部编码`（默认，与原现网模板一致）、`50*30 编码+名称+快递单号`、`40*30 编码+订单号`；
   - 打印机、份数（1–100）、是否「直接打印前先调用系统预览」；
   - 内置 canvas 预览是**示意图**，条码为条纹示意，真实条码由 C-Lodop 生成；
   - 模板/打印机/份数/预览选项会保存到本机，下次自动恢复。
3. 点「系统预览」或「直接打印」。
4. **打印前会自动读取远端最新数据并按编码复核**：商品被删除/改名/不存在时会中止或跳过并提示；批量打印为 strict（全有或全无）。
5. 回收站中的商品不能打印；会提示先恢复。
6. 字段为 `null` 时按空字符串处理（不会打出 "null"）。
7. 未安装/未启动 C-Lodop 时，仍可看内置示意图；系统预览/打印会提示不可用。

> 打印效果与打印机、驱动、纸张、C-Lodop 版本有关，**首次使用请现场用真实打印机验证**。份数顺序已修复；如仍有异常，记录模板/纸张/驱动/打印机型号反馈。

## 5. 日常习惯与注意事项

- **先备份再批量操作**：导入、批量改状态、批量删除前先「导出备份 JSON」。
- **定期导出**：至少每周一次；Token 换新前导出；**Gist 删除不可自助恢复，导出文件是最后退路**。
- **不要在 Gist 里放敏感数据**：Secret Gist 不是私有，链接即权限。
- **不要随意改编码**：改名会级联，旧标签失效。
- **回收站不是删除**：彻底删除才真正移除。
- **手机端别用内嵌浏览器**：摄像头/相册权限可能受限。
- **打印需现场验证**：页面预览只是参考。
- **Token 只在本机**：共用电脑默认不记住、用完退出；必要时清理浏览器数据。

遇到问题先查 [FAQ](FAQ.md)；数据恢复见 [备份与恢复](BACKUP-AND-RECOVERY.md)。

## 6. v2.3.0 使用要点（编码 / 类目条码 / 保存）

### 6.1 自定义编码

- 点「自定义编码（高级）」后手填**本级段**：大写字母、小写字母、数字可混搭（如 `AB12`、`YO3`），**不能写中文**。
- 子类/库存的父编码前缀是固定的，只需要填本级；例如父 `NN` 下填 `YO3`，保存后完整编码为 `NN/YO3`。
- 不勾选自定义时，系统会按同级格式自动给下一个编码：同级有 `NN/YO1`、`NN/YO2` → 自动 `NN/YO3`。

### 6.2 类目条码与单件条码

- 节点弹窗里「类目条码」选“是”：该节点代表整个类目，**成本/快递单号/订单号输入框会隐藏并清空**；状态不再手填，而是显示“全部在售 / 部分在售 / 全部售出 / 部分售出 / 全部待售 / 部分待售 / 无库存”。
- 选“否”：按单件管理，每个库存单独编码，可记录成本/单号并手填状态。
- 扫码端扫到类目条码时，会显示“类目条码”和汇总状态，不展示成本/单号。

### 6.3 保存

- 点保存后界面立即生效、弹窗立即关闭；顶部显示保存进度，几秒内变“✓ 已保存”。
- 可以连续编辑多个商品，系统会按顺序合并写入；保存失败会提示并回滚，冲突会弹字段级选择框。
