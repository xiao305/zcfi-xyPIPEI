# 用户手册（管理后台 + 扫码端）

本手册面向**最终用户**，照着做即可完成首次配置和日常操作。
不想看长文？先看 [README 的首次使用](../README.md#首次使用5-步)，再回来查细节。

---

## 1. 开始前需要准备什么

| 准备项 | 说明 |
| --- | --- |
| GitHub 账号 | 数据存在 GitHub Gist 里，必须有账号 |
| 一个 Gist（数据文件） | 文件名固定建议 `data.json`，内容先写 `{"products":{}}` |
| GitHub Token | 只给 Gist 读写权限；只显示一次，务必保存 |
| 一个浏览器 | 电脑用 Chrome/Edge；手机用 Safari/Chrome。手机扫码需 HTTPS 和摄像头权限 |
| C-Lodop（只打印需要） | 安装在本机电脑并保持运行 |

### 1.1 创建数据 Gist

1. 登录 <https://gist.github.com>。
2. 文件名：`data.json`。
3. 内容：`{"products":{}}`（先建空库，后面用后台加商品）。
4. 点「Create secret gist」（推荐 Secret，避免被搜索到）。
5. 创建后，浏览器地址类似：

   ```
   https://gist.github.com/你的用户名/f13d97c430522e4851afbf3cd2331e14
   ```

   最后一段 `f13d97c430522e4851afbf3cd2331e14` 就是 **Gist ID**。
   登录框里默认的 Gist ID 是示例值，**请换成你自己的**。

### 1.2 创建 GitHub Token

推荐 Fine-grained token：

1. GitHub 右上角头像 → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token。
2. Token name 随便填（例如 `zcfi-scan`），Expiration 按需。
3. 权限只勾 **Gists: Read and write**。
4. Generate → 复制 Token（`github_pat_...` 或 `ghp_...`）。

> 不要把 Token 发给任何人，不要贴到聊天、截图、Issue、代码里。怀疑泄露立即 Revoke。

### 1.3 登录

打开管理后台或扫码端，填写 Token / Gist ID / 文件名 → 登录。

- 失败时先看错误提示：401 多半是 Token；404/文件不存在看 Gist ID 和文件名。
- 更多错误见 [FAQ](FAQ.md)。

## 2. 管理后台 `/admin`

### 2.1 页面布局

- 顶部：登录状态/最后同步时间/数据版本/打印服务状态；添加大类、刷新、数据菜单、退出。
- 筛选栏：按大类筛选、搜索框（编码/名称/单号/备注/状态/链接）。
- 商品树：每个节点显示名称、编码、统一条码、状态、订单号；节点下可展开子类和库存表。
- 回收站/数据工具：在「🗄 数据」菜单里。

### 2.2 建商品树

1. **添加大类**：顶部「＋ 添加大类」。
   - 名称必填。
   - 编码默认自动生成 `A001`、`A002`……，一般不用改。
2. **添加子类**：在「统一条码=是」的节点行点「添加子类」，生成 `A001/B001`。
3. **添加库存**：在「统一条码=否」的节点行点「添加库存」，生成 `A001/B001/001`。
4. 每个库存是独立的一件商品，可单独设置成本、快递、订单、状态、备注。

> 「统一条码」含义：是=该节点下继续加子类；否=该节点下加库存。已有数据按原设置使用，不建议随意切换后混用。

### 2.3 编辑节点/库存

点行内「编辑」：

| 字段 | 说明 |
| --- | --- |
| 名称 | 必填 |
| 编码 | 默认只读；高级用户可勾「自定义编码」手填，必须符合格式且全局唯一 |
| 统一条码 | 决定该节点下加子类还是库存 |
| 状态 | 待售 / 在售 / 售出 |
| 成本 | 数字，可空 |
| 快递单号 | 手填或扫码关联写入 |
| 订单号 | 手填或扫码关联写入 |
| 链接 | 多个链接用英文/中文逗号或换行分隔 |
| 备注 | 任意文本 |

保存时：
- 只提交实际修改的字段，不会整库覆盖。
- 如其它设备同时改了同一字段，会弹出冲突窗，逐项选择「用我的」或「用远端」。
- 正在保存时其它按钮会暂时不可用，避免重复提交。

### 2.4 编码规则（重要）

| 层级 | 格式 | 示例 |
| --- | --- | --- |
| 大类 | `A` + 三位数字 | `A001` |
| 子类 | 父编码 + `/B` + 三位数字 | `A001/B001` |
| 库存 | 父编码 + `/` + 三位数字 | `A001/B001/001` |

- 节点与库存编码**全局唯一**（包括回收站中的，彻底删除后才释放）。
- 改名会级联更新下级编码；**旧标签/旧二维码会失效**，需要重新打印。
- 不建议手工输入带空格、大小写混杂的编码；扫码端会做 trim/忽略大小写匹配。

### 2.5 搜索 / 筛选 / 批量

- 搜索框支持编码、名称、订单号、快递单号、备注、状态、链接；清空后恢复全部。
- 选择大类后只看该大类。
- 库存表可勾选多项：
  - **批量打印**：把选中的库存一起打印。
  - **批量修改状态**：把选中库存统一改成某状态。
- 已删除（回收站）的项不会出现在搜索/筛选/打印中。

### 2.6 删除与回收站

- 行内「删除」→ 输入编码确认 → **移入回收站**（软删除，数据还在 Gist）。
- 回收站里可：
  - **恢复**：恢复节点/库存；如果父节点还在回收站，必须先恢复父节点。
  - **彻底删除**：永久移除，不可恢复；节点会连同其子类和库存一起删除。
- 删除父节点时整棵子树都会被隐藏；恢复父节点后子项重新可见。
- 彻底删除会释放编码，之后可重新使用该编码。

### 2.7 数据菜单（导出/导入/体检/历史/快照）

| 菜单 | 使用场景 | 注意 |
| --- | --- | --- |
| 导出备份 JSON | 定期备份、改数据前备份 | 文件保存到你电脑 |
| 导入 JSON | 换电脑/恢复备份 | 会替换当前全部商品数据；导入前自动下载当前备份；结构错误会禁止导入 |
| 数据体检 | 数据异常/导入前检查 | 统计节点/库存/回收站，列出 errors/warnings |
| 历史版本 | 误操作后回滚 | 查看 Gist 提交版本与差异，恢复前自动备份；恢复是整库替换 |
| 本地快照 | 最近几次保存的快速回退 | 每次保存前自动记录，最多 3 份；超过 1.5MB 会跳过 |
| 回收站 | 恢复误删 | 见上 |

### 2.8 记住登录

- 勾选「记住登录（本机）」：Token 保存到 `localStorage`，下次打开自动登录。
- 取消勾选：Token 只保存到 `sessionStorage`，关闭浏览器/标签页后失效。
- 「退出」会清理本地保存的凭据。
- 共用电脑建议取消勾选，用完退出。

## 3. 扫码端 `/scan`

### 3.1 登录与摄像头

1. 打开 `/scan`（手机浏览器），登录。
2. 点「开始扫码」，浏览器询问摄像头权限 → 允许。
3. 摄像头画面出现后，把二维码/条形码/PDF417 放入取景框。
4. 识别成功会有短震动/提示音（设置可关）。

> 手机必须用 HTTPS；iOS Safari 需要较新版本；微信/QQ 内置浏览器可能限制摄像头，建议用系统浏览器打开。

### 3.2 扫码后

- 命中 1 个商品：底部抽屉显示详情。
- 命中多个（同一订单号/快递号重复）：
  - 弹出候选列表，顶部黄条提示「该单号命中 N 个商品，请确认」。
  - 点选正确的一项进入详情。
- 未命中：弹窗提示；点「继续扫描」回到扫码；也可查看历史。
- 命中已删除商品：提示「该商品已删除，请到后台回收站恢复」，不会进详情。

### 3.3 连续模式

- 顶部「连续模式」默认开启：
  - 命中商品后摄像头保持开启，只暂停解码回调；
  - 关闭详情抽屉后直接继续扫，不需要重新点开始；
  - 未找到弹窗点「继续扫描」、关联成功点「继续扫下一件」也都不重启摄像头。
- 关闭「连续模式」：每次扫码后会停止摄像头，需手动点「开始扫码」。设置保存在本机。

### 3.4 关联快递/订单/链接

1. 打开商品详情 → 点「扫描关联信息」。
2. 扫描或手动输入要关联的内容：
   - 以 `http://` / `https://` 开头 → 链接
   - 符合常见快递单号格式 → 快递单号
   - 其它 10 位以上纯数字 → 订单号
3. 在关联确认弹窗可手动改类型；如果商品已有同类型值，会提示替换/已绑定。
4. 可勾选「关联后标记为售出」。
5. 点「确认关联」：
   - 成功：详情更新，出现「继续扫下一件」。
   - 失败：保留在弹窗里，提示错误，可点「重试保存」。

### 3.5 图片识别

1. 点「图片识别」。
2. 从相册/文件选择二维码截图。
3. 图片只在本机解码，识别结果走与摄像头相同的查询流程。
4. 失败时换清晰图片。

### 3.6 历史

- 历史按日期分组，点记录可回看商品。
- 「更多 → 清空历史」需确认；清空后 12 秒内底部「撤销」可恢复最近 20 条。
- 历史只在本机，不占 Gist。

### 3.7 数据刷新/离线

- 顶部显示「数据更新于 HH:mm」，点 ⟳ 手动刷新。
- 后台每 30 秒自动刷新；页面重新可见时也会刷新。
- 断网时显示离线提示，仍可用缓存匹配；保存时会重新联网，失败可重试。

### 3.8 设置

「更多 → 设置」：

- 连续扫码模式（与顶部开关同步）
- 扫码成功震动
- 扫码成功提示音

设置保存在本机浏览器。

## 4. 标签打印（管理后台）

1. 在电脑安装并启动 **C-Lodop**。
2. 打开 `/admin`，顶部应显示「✅ 打印服务已就绪」。
3. 如果提示未连接或证书错误：
   - 浏览器另开 `https://localhost.lodop.net:8443`，选择信任证书，再刷新后台。
4. 商品/库存行点「打印标签」；多个库存勾选后「批量打印」。
5. 选择模板（当前 `50*30标签`）、打印机、份数。
6. 「预览（无水印）」检查；确认后「直接打印」。
7. 回收站中的商品不能打印；会提示先恢复。

> 打印效果与打印机、驱动、纸张、C-Lodop 版本有关，**首次使用请现场用真实打印机验证**。份数/模板等 R3 会继续完善。

## 5. 日常习惯与注意事项

- **先备份再批量操作**：导入、批量改状态、批量删除前先「导出备份 JSON」。
- **定期导出**：至少每周一次；Token 换新前导出。
- **不要随意改编码**：改名会级联，旧标签失效。
- **回收站不是删除**：彻底删除才真正移除。
- **手机端别用内嵌浏览器**：摄像头/相册权限可能受限。
- **打印需现场验证**：页面预览只是参考。
- **Token 只在本机**：共用电脑用完退出；必要时清理浏览器数据。

遇到问题先查 [FAQ](FAQ.md)；数据恢复见 [备份与恢复](BACKUP-AND-RECOVERY.md)。
