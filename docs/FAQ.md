# 常见问题（FAQ）

先对号入座；解决不了再看 [用户手册](USER-GUIDE.md) 或 [备份与恢复](BACKUP-AND-RECOVERY.md)。
版本基线：v2.2.0（core 2.2.0 / admin R4 / scan R3），2026-11-13。

---

## 入口与安全

### Q1：站点根路径 `/` 是什么？我该从哪里进？

- `/` 现在是**导航页**（不是扫码测试页）：只做两个入口和安全提示，纯静态、无脚本、无 CDN。
- 管理后台：`https://xypipei.zcfi.cn/admin`
- 手机扫码：`https://xypipei.zcfi.cn/scan`
- 扫码库调试页（一般不用）：`https://xypipei.zcfi.cn/tools/scanner-test.html`，标注「调试用」且 `noindex`。

### Q2：Secret Gist 是私有的吗？

- **不是。** GitHub 的 Secret Gist 只是「不公开列出」，**拿到链接的人无需登录即可读取**（GitHub 官方文档也明确 Secret gist 不是私有）。
- 也就是说 **链接即权限**：公开 Gist 可能被搜索引擎/他人发现；Secret Gist 只要链接外传，同样会被读。
- 建议：不要把成本、订单号、快递单号、客户信息等敏感数据放进 Gist；用专用账号、定期轮换 Token；数据安全以**本地导出备份**为最终保障。

### Q3：Token 会被页面传到别处吗？

- 不会发给其它域名。Token 只保存在本机浏览器，请求时**只在 `Authorization` 头发送给 `api.github.com`**；不进 URL、日志、Gist。
- 但 Token 会随每次 GitHub 请求发送，这是 API 必需行为。仍要防 XSS/共用电脑：不使用来源不明的脚本，共用电脑用完退出。
- `gists` 权限是**账号级**的：Token 泄露 = 该账号下全部 Gist 可读写，怀疑泄露立即 Revoke 并重新生成。

### Q4：怎么清除本机登录与历史？

- **退出登录**（两页都有）：会清理 local/session 两处凭据。
- **扫码历史**：`/scan` →「更多 → 清空历史」；退出登录时也可选择一并清理本机历史。历史按 Gist ID 隔离，不会串账号。
- **本地快照/视图/打印设置**：在后台换 Gist/退出时会清理非当前 Gist 的快照；视图/打印设置可在浏览器站点数据里清除。
- **彻底清理**：浏览器设置 → 站点数据/清除浏览数据 → 选择本站点清除（会同时清掉本机快照、历史、设置与「记住登录」凭据）。

## 登录与权限

### Q5：登录提示 401 / Token 无效或过期？

- Token 复制不完整、过期、被撤销，或没有 Gist 权限。
- 重新生成 Token：Fine-grained token 勾 **Gists: Read and write**；Classic token 只勾 `gist`。
- 粘贴时注意不要带空格/换行。
- 若使用 Fine-grained token，确认该 Token 被允许访问你的 Gist（资源所有者/账号正确）。

### Q6：登录提示 404 / 找不到 Gist 或文件？

- Gist ID 不对：从 Gist 地址最后一段重新复制。
- 文件名不对：默认 `data.json`；你的 Gist 里文件名必须完全一致（区分大小写）。
- Gist 被删除/转移。
- **Token 没有 `gist` 权限时，GitHub 往往也返回 404**（而不是 403）——所以 404 要同时怀疑「Gist/文件名不对」和「Token 权限不对」。
- 错误码 `FILE_MISSING` 通常就是「这个 Gist 里没有这个文件名」。

### Q7：403 和 404 分别意味着什么？

| 状态 | 常见原因 | 页面/核心错误码 | 怎么办 |
| --- | --- | --- | --- |
| **401** | Token 无效/过期/被撤销 | `AUTH` | 重新生成 Token 并登录 |
| **403（限流）** | GitHub API 频率超限（`X-RateLimit-Remaining: 0`，或带 `Retry-After`） | `RATE_LIMIT`（带 `retryAfter`） | 等提示的秒数/几分钟再试；不要连续点刷新 |
| **403（权限）** | Token 缺少 `gist` 权限、被组织策略限制、访问了无权 Gist | `PERMISSION` | 检查 Token 权限与账号；重新生成最小权限 Token |
| **404** | Gist ID 不存在、文件名不存在、Gist 已删、Token 无 `gist` 权限 | `FILE_MISSING` | 核对 Gist ID 与文件名；确认 Token 有 gist 权限 |

> 页面会尽量区分限流/权限/不存在，并给出中文提示；`403` 不一定都是 Token 坏了，先看是不是**限流**。

### Q8：「记住登录」默认勾选吗？两页一致吗？

- **默认不勾选**（v2.2.0 起）。`/admin` 与 `/scan` 行为一致：
  - 勾选 → `localStorage`，关闭浏览器后仍自动登录；
  - 不勾选 → `sessionStorage`，关闭标签页/浏览器后失效；
  - 读取时 sessionStorage 优先于 localStorage；
  - 退出登录同时清理两处；切换勾选时会清理另一种存储。
- **共用设备风险**：勾选记住 = Token 留在本机浏览器；公共/共用电脑请保持不勾选，用完退出（可同时清历史）。

### Q9：两页登录状态会互相影响吗？

- 同一浏览器下两页共享凭据（键同名），可以互通；多标签页会通过 `storage` 事件同步退出/登录状态。
- 遇到自动登录成旧账号/旧 Gist：在两个页面都「退出」，必要时清理浏览器站点数据后重新登录。

## 数据与加载

### Q10：提示「数据文件过大 / 被截断」？

- GitHub Gist API 对超过约 **1 MB** 的文件只返回部分内容，页面会尝试用 `raw_url` 拉全量；仍失败会报 `TRUNCATED` 并停止加载，防止用残缺数据覆盖远端。
- 处理：
  1. 先在后台「导出备份 JSON」；
  2. 清理回收站/不再使用的商品/库存；
  3. 减少冗余字段和超长备注；
  4. 保持 `data.json` 在 1 MB 以内。
- 当前是单文件设计，不能自动拆分；数据量很大时建议分多个 Gist/多套数据使用。

### Q11：提示 JSON 损坏 / 结构异常 / 空文件？

- `PARSE`：文件不是合法 JSON。用备份恢复（历史版本/导出备份）。
- `SCHEMA`：缺少 `products` 对象或结构不对。不要强行保存，先恢复备份。
- `EMPTY`：文件内容为空。同样建议恢复备份。
- 这些情况下页面会进入**只读保护**，不会写入，避免覆盖唯一数据。

### Q12：如何强制刷新远端数据？

- 后台顶部「刷新」/ 扫码端顶部 `⟳` 手动刷新（保存前本来就会重新 `GET` 远端，且请求 `cache:'no-store'`）。
- 也可以刷新页面或重新登录；扫码端页面重新可见时会自动刷新。
- 若怀疑有并发修改：先刷新，再操作；冲突时会弹逐字段选择。

### Q13：后台「版本：未知」是什么意思？

- Gist 历史版本接口暂时不可用/Token 权限不足，页面无法显示 revision。
- 数据照常读写；只是版本号显示未知，不影响使用。

### Q14：保存时弹「检测到冲突」怎么选？

- 说明同一字段被其它设备/扫码端同时改了。
- 后台/扫码端都提供**逐字段**选择：
  - 「用我的」= 保留你这次修改；
  - 「用远端」= 采用对方修改。
- 不确定时先「用远端」保存，再重新改一次，避免覆盖对方。

### Q15：保存失败/断网怎么办？

- 页面会提示错误，本地不会保留「失败的数据」；恢复网络后点「重试保存」。
- 扫码端断网时会显示离线提示，仍可用缓存匹配；保存需要联网。
- 后台刷新失败会进入只读错误态，点「重试」重新加载，成功前不会写入。

### Q16：自动本地快照为什么有时候没有？

- 后台每次保存前最多保留 3 份；数据超过约 1.5 MB 时会跳过自动快照（避免占满浏览器存储），但远端保存仍正常。
- 快照**按 Gist ID 隔离**，换账号/退出后看不到其他 Gist 的快照。
- 换浏览器/清理站点数据会丢失快照；请以手动导出 JSON 为准。

### Q17：编码大小写/重复怎么办？

- 后台在**导入/数据体检**时会检查编码大小写：
  - 大小写不同但实际相同的编码（如 `A001` 与 `a001`）会作为 **errors** 阻止导入；
  - 非大写编码会提示 warning「建议统一大写」。
- 保存时节点与库存编码按忽略大小写做全局唯一校验；扫码端匹配也忽略大小写。
- 编码归一（`normalizeCode`）会**去除零宽字符与所有空白（含全角空格）**。
- 建议：内部编码统一大写、不要手工制造大小写差异；改名后旧标签/旧二维码会失效，需要重打。

## 扫码端

### Q18：摄像头打不开/黑屏？

- 必须 HTTPS；GitHub Pages 默认满足。
- 浏览器/系统设置里允许本站摄像头权限。
- 不要用微信/QQ 内置浏览器，改用 Safari/Chrome。
- iOS 需要较新系统版本（Safari 15.1+ 对网页摄像头支持较好）。
- 关掉其它占用摄像头的 App；重新打开页面再试。
- 实在不行用「图片识别」或手动输入。

### Q19：扫码没反应/提示未找到？

- 检查标签是否是旧编码：后台改过编码后，旧标签/旧二维码会失效，需要重新打印。
- 手动输入框可以输入内部编码/订单号/快递单号验证数据是否存在。
- 用「图片识别」试截图。
- 光线太暗可开手电筒（支持时）；太近/太远调整距离。

### Q20：手电筒按钮不见了？

- 只有设备/浏览器支持 torch 能力时才显示；不支持会隐藏，属正常降级，不是故障。

### Q21：命中多个商品/订单号重复？

- 同一订单号/快递号可能被多个商品使用；页面会弹候选列表，顶部黄条提示「该单号命中 N 个商品，请确认」。
- 点选正确商品再操作，避免关联/标错。

### Q22：扫到「已删除」商品？

- 该商品在后台回收站。去后台「🗄 数据 → 🗑️ 回收站」恢复后再扫。
- 彻底删除的商品无法恢复，只能靠备份。
- 扫码历史中对应记录也会置灰并显示灰色「已删除」徽章；点击仍会提示，不会进入详情。无 ref 的旧历史记录不会显示该徽章。

### Q23：历史记录刷新/换手机后没了？

- 扫码历史只存在本机浏览器，不同步、不写 Gist；换设备/清缓存会丢。
- 历史按 Gist ID 隔离；退出登录可同时清理。
- 需要追溯请及时处理，或使用后台的 Gist 历史版本（那是数据版本，不是扫码流水）。

### Q24：清空历史能恢复吗？

- 清空后 12 秒内点底部「撤销」可恢复最近 20 条；超时/刷新后不能（撤销备份会被删除）。

### Q25：多个标签页同时用会乱吗？

- 登录/退出/历史通过 `storage` 事件同步；历史按记录合并，不会整键覆盖。
- 两端同时改同一商品仍会触发冲突提示，按逐字段选择处理。

## 打印（C-Lodop）

### Q26：顶部显示「打印服务未连接」怎么办？

- 本机安装并启动 C-Lodop；任务栏应有图标。
- 防火墙/杀毒软件可能拦截，放行 C-Lodop。
- 刷新后台页面。
- 页面从本机加载打印脚本：HTTPS 页面用 `https://localhost.lodop.net:8443/CLodopFuncs.js`（**不会**回退 http），HTTP 页面用 `http://localhost:8000/CLodopFuncs.js`；仓库不再内置 `CLodopFuncs.js`。
- 即使未连接，仍可打开打印弹窗看**内置示意图**；系统预览/直接打印会明确报错，**不会假成功**。

### Q27：HTTPS 下提示证书错误/无法加载？

- 浏览器新开 `https://localhost.lodop.net:8443`，选择「继续访问/信任证书」。
- 回到 `/admin` 刷新；仍不行重启 C-Lodop 再试。
- 页面**只在点打印/预览时**才连接本机服务（v2.2.2 起，页面加载/登录时不再请求，避免一打开后台就弹出「访问本地网络」授权）；连接顺序为 **`http://localhost:8000` 优先**（可绕开 8443 可能过期的证书），失败再试 HTTPS:8443。两者都失败会提示打印服务不可用。

### Q28：能预览但打印没反应/份数不对/内容错位？

- 检查是否选了真实打印机（不是 PDF/虚拟打印机）；打印机列表来自本机 C-Lodop 实时列表。
- 检查纸张尺寸是否与模板一致（50×30 / 40×30 / 50×40mm），打印机驱动设置是否一致。
- **打印结果以状态栏为准**：页面注册了 C-Lodop 的 `On_Return`，成功/失败会显示；不再出现“提示已发送但没出纸”的假成功。
- **份数已修复**：指令顺序为 `PRINT_INIT → SET_PRINT_PAGESIZE → SET_PRINT_COPIES → 内容 → PRINT/PREVIEW`。
- **打印设置会记忆**：模板、打印机、份数、「打印前先预览」保存在本机；上次打印机不可用会回落默认并提示。
- **打印前会复核远端**：点「直接打印/系统预览」前会重新读取 Gist 并按编码重新解析；有商品被删除/改名/不存在时会中止或跳过并提示。
- **批量打印 strict**：复核有失效条目会取消整批并列出被跳过条目，不会只打一部分却提示成功。
- 页面内置 canvas 预览只是版式示意图，字体/边距/条码以 C-Lodop 实际打印为准；**真实打印必须现场验证**。

### Q29：回收站里的商品能打印吗？

- 不能。页面会提示先恢复；避免把已删除商品的旧标签再打出来。

## 备份/恢复

### Q30：恢复/导入会覆盖远端吗？

- 会。导入 JSON、恢复历史版本、恢复本地快照都是用备份数据**替换**当前 `products`。
- 系统会在恢复前**先从远端拉取最新数据并下载 `backup-before-<时间>.json`**，再二次确认；被覆盖的内容可用这份备份找回。
- 仍建议在恢复前手动「导出备份 JSON」。

### Q31：Gist 被误删了怎么办？

- GitHub **没有面向用户的 Gist 回收站**，删除后**无法自助恢复**；只能立即**联系 GitHub Support** 尝试找回（不保证成功）。
- 因此**本地导出的 JSON 才是最终保障**：有导出就新建 Gist 导入；没有导出可能永久丢失。

### Q32：数据能多人同时用吗？

- 可以，但**没有账号/权限体系**：拿到同一个 Token + Gist ID 的人都能读写。
- 多人同时保存会触发字段级冲突提示；请避免同时改同一商品。
- 建议一个团队共用一个专用 Gist + 最小权限 Token 管理好；共享 Gist 对拿到链接者可能是可读的。

### Q33：为什么建议 1 MB 以内？

- GitHub API 单文件内容超过约 1 MB 会截断；页面虽有 `raw_url` 回退，但数据越大加载越慢、失败风险越高。
- 定期导出、清理回收站、删除无用商品。

## 编译/部署/维护

### Q34：改了 GitHub 上的文件多久生效？

- GitHub Pages 通常 1–3 分钟；强缓存时 Ctrl/Cmd+Shift+R 强制刷新。
- 自定义域名由 `CNAME` 控制，DNS 需指向 GitHub Pages。

### Q35：能离线使用吗？

- 页面是静态文件，理论上可缓存，但当前**没有** Service Worker 离线包；断网时页面需已打开，数据用浏览器缓存，扫码匹配仍可用但保存要联网。
- 需要真正离线请后续规划 PWA。

### Q36：发布前怎么自检？

- 在仓库根目录执行 `node tools/verify.mjs`（静态/语法/文档一致性），并确认 `.github/workflows/ci.yml` 为绿。
- 详细步骤见 [发布检查清单](RELEASE-CHECKLIST.md)。

## v2.3.0 新增功能

### Q34：自定义编码能写什么？中文可以吗？

- 本级编码段只允许**英文字母 + 数字（可混搭）**，例如 `AB12`、`YO3`、`X1`。
- **不允许中文**、空格与特殊符号；不符合会提示。
- 子类/库存只能改**本级段**：父编码前缀固定不可改，例如父 `NN` 下填 `YO3` → 完整编码 `NN/YO3`。

### Q35：为什么新建子类自动给了 `NN/YO3`？

- v2.3.0 起自动编码会**跟随同级已有格式**：同级有 `NN/YO1`、`NN/YO2` 时，下一个自动为 `NN/YO3`（字母前缀 + 递增数字，位数沿用）。
- 同级是 `A001`、`A002` 时给 `A003`；没有同级时回退默认 `A001` / `B001` / `001`。

### Q36：「类目条码」（原“统一条码”）是什么意思？

- 是：整个类目共用一个编码，**不记录成本/快递单号/订单号**；类目状态由该类目下商品自动汇总（全部在售/部分在售/全部售出/部分售出/全部待售/部分待售/无库存）。
- 否（单件条码）：每个库存单独编码，可记录成本/快递/订单并手动维护状态。

### Q37：为什么现在保存很快、弹窗直接关了？

- v2.3.0 起保存改为**乐观更新 + 后台写入 + 排队合并**：界面立即生效、弹窗立即关闭，顶部显示“⟳ 保存中… / ✓ 已保存”。
- 连续修改会合并成一批写入；失败会提示并回滚到远端最新数据；冲突仍会弹逐字段冲突框。

### Q38：实际打印和页面里看到的排版不一样（字被截断/条码歪）怎么办？

- v2.3.1 已修复：单行文字改用 LODOP 原生文本（字号精确，不再被 HTML 渲染放大而截断），字号按 LODOP 的半角/全角字宽差异校准；PDF417 去掉了导致旋转的样式，条码正立。
- 页面内预览已改为与打印同源的 mm/pt 排版；条码在预览中是 PDF417 2D 形态示意，实际条码由 C-Lodop/打印机生成，尺寸/留白以实打为准。
- 新增 **50\*40** 模板（共 4 套），在打印弹窗「标签模板」里切换。
- 若仍异常：确认打印机纸张尺寸与模板一致、驱动中自定义纸张为 50×30 / 50×40mm；「设置 → 系统预览」可看 C-Lodop 的实际排版。


### Q39：标签上的「内部编码：xxx」能改显示方式吗？入库/出库模板怎么选？

- 能。打印弹窗「编码文字」三选一（v2.3.2）：
  - **最后一级**（默认）：`内部编码：001`；
  - **完整编码**：`内部编码：A001/B001/001`（超长自动缩小字号保持单行）；
  - **仅“内部编码”**：只显示这四个字，编码只在条码里。
  设置会记忆，对所有模板生效。
- 模板按 **公共 / 入库 / 出库** 分类：打印弹窗顶部先选「入库 / 出库」，公共模板（50\*30 内部编码）两类都可用。
- **入库标签不含订单号、快递单号**（当前入库模板：50\*30 编码+名称+条码、40\*30 编码+条码）；出库标签可按需要选择含快递/订单的模板。
- 商品名称统一 10pt 黑体、单行优先（超长会自动缩小，最小 6pt）。


### Q40：40\*30 的条码又窄又高，扫不出来怎么办？/ “仅内部编码”旁边空白能放字吗？

- **40\*30 全系条码已改宽扁**（v2.3.3）：PDF417 对象改为 42×8.5mm，实测墨迹约 38.9×8.3mm（宽高比 4.67，旧版 26×16mm、比例 1.6），宽扁更易扫。
- **自定义文本**（v2.3.3）：当编码文字选「仅“内部编码”」时，「内部编码」左对齐、右侧可打印自定义文本；打印弹窗可填内容并选字号 **5/6/7/8pt**（默认 6），设置会记忆。内容过长会先缩到 5pt，仍放不下则截断加省略号。
- 其他编码文字模式（最后一级/完整编码）不显示自定义文本。
- 新增 **50\*40 入库模板**（第 7 套，编码+名称+大条码，无订单/快递）。


### Q41：真机打印条码偏右/大小异常，预览却是好的？

- v2.3.5 已修复：此前按“预估墨迹宽”反推条码对象左边界，对象框会**超出纸张**；C-Lodop 预览容忍越界，真机驱动裁切/重锚定后表现为偏右、尺寸异常。
- 现在改为：按“条码高度 × 编码长度档”用真实预览标定**实测墨迹宽**，把对象框宽设为该墨迹宽再水平居中；7 套模板实测左右留白差 ≤1.06mm。
- 同时所有打印项限制在 **2mm 打印安全区**内（左右各 2mm 不打内容）；
- 「仅内部编码」模式下自定义文本支持**多行**，且底边不会低于「内部编码」所在行的底边。
- 若个别编码长度仍差 1~2mm：属 PDF417 列数量化，可反馈具体编码长度再补标定档位。
